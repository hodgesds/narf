# GPU Rust tests and retained fixture data

GPU driver tests exercise production Rust modules directly through the kernel
model harness. Register ordering, wire fields, bounds, ownership, cancellation,
recovery and capability admission remain testable without an external compiler
or a Linux/Mesa checkout. These internal tests do not establish conformance to
an external implementation, physical GPU operation, or application acceptance.

The data files in this directory are retained regression inputs and expected
values. Their original Linux/Mesa source provenance remains relevant, but they
are reviewed static fixtures, not outputs regenerated by an in-tree source
extraction or C comparison pipeline. Existing Rust tests consume these files
through `include_str!` and `include_bytes!` and invoke the production functions.
Changes to fixtures require review of the underlying hardware/ABI contract;
regenerating expected values from the implementation under test is insufficient.

The former C/C++ reference shims, Python source slicing/temporary Rust harnesses
and shell compiler drivers have been removed. Their absence does not turn
internal regression agreement into independent external acceptance. Selected
Mesa/libdrm applications must eventually exercise the actual NARF device/ioctl
boundary, and physical diagnostics must complete on supported hardware.

Required production data is preserved: AV1 decoder/encoder CDFs, scaler filters,
shader/PM4 words, codec picture assets, their hashes and upstream license
notices. The shader assembly listing is retained as human-readable provenance.
The five remaining Python picture generators call explicitly supplied codec
executables to create original media assets; they neither extract/compile C
or Rust sources nor replace native Rust driver tests.
