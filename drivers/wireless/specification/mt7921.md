## 1. Purpose & scope

The built-in `narf-drivers-wireless-mt76` crate owns CONNAC2 PCI discovery,
register access, firmware/MCU transport and the MT7921/MT7922 radio interface.
The loadable frontend now has a versioned copy-mode service boundary to the
permanent native host. It owns probe/service/control handles and its
domain-gated poller; MCU/WFDMA machine code, verified executable images,
async futures and the actual netdev/wiphy remain host-resident. This is a
hosted loadable packet/control ABI, with software acceptance recorded in §3;
physical-device module execution remains outside that acceptance. It does not claim that the full native engine moved into `.ko`.

## 2. Assumptions

The live transport targets x86_64 and aarch64 with coherent identity DMA and exclusive
device/BAR/latch ownership. Behind the opt-in per-domain IOMMU
(`iommu.passthrough=0`) all transport DMA is mapped through the function's
own domain (§5 "Per-domain IOMMU"). Firmware and published DMA remain
retained until verified shutdown or, behind that IOMMU, a completed DMA
block.

One retained operation per service prevents unbounded native work. Request
bytes are copied and zeroized on release. Poll returns `-EAGAIN` until an
actual native terminal result; `-ENOBUFS` retains the reply and reports its
required size. Cancelling before the first poll returns `-ECANCELED` without
native execution. A started operation keeps its future/resources until its
actual result; a successful effect after cancellation returns `-EALREADY`
and may have taken effect. Close/unload withdraws the exact native generation,
parks mastering through the established removal path, revokes the original
probe grant, and retains started work in a permanent cleanup task. Unproven
DMA remains retained, including when revocation prevents proving idle.
No host future or registered interface points into unloadable module text.

### Native AP BSS and beacon owner

`Transport::start_ap(Arc<ApControlAuthority>, ApConfig)` and `stop_ap` drive
native BSS0/OMAC0 firmware commands. The trusted caller must pair that transport
with the concrete registered interface and use `authority.check_for(iface)`;
the request guard does not by itself establish PCI-device binding. Startup
checks the bound registered MAC and administrative-UP identity, prevalidates
the actual beacon/probe templates and current regulatory domain, then verifies
a fresh WFSYS generation before installing DEV, MAC/RX, domain/SKU,
channel, AP BSS/RLM, CE BSS abort/connected, BMC WCID19 WTBL and the embedded
beacon TXD/template. Native MAC timing pauses ARB TX/RX, awaits at least1µs
under the current request/RF owner, applies actual band SIFS, requested slot and
CFEND/timing fields, and verifies readback before reopening ARB. Capture receives a fresh actual backend epoch after reset
recycles its metadata. The CE commands have no response; the native PSE progress
receipt bounds them without inventing a firmware ACK. Every AP command wait
rechecks current request authority and occupied-channel permission. A dropped
borrowed waiter leaves its retained running owner quarantined; neither a pending
command nor `State::AccessPoint` opens host carrier or a station controlled port.
Stop, non-WoW suspend and shutdown stop the autonomous BSS and verify MAC/FW reset
before retiring the AP owner. Failed reset retains the uncertain owner.

The concrete-interface `commit_ap_start` owner method opens a fresh BSS copy
lease only after native START and a current request reservation; it opens no
peer port. `add_ap_station` reserves WCID1–13 before the native STA/WTBL command,
validates AID1–20/common legacy rates and commits the peer only after its actual
receipt. Firmware BASIC uses PORT_SECURE2 independently of the host controlled
port, matching Linux. `authorize_ap_station` changes only host admission and the
copy epoch; an AUTHORIZED-only update must not reset WTBL/native sequence state.
A secure port requires an installed current PTK. `delete_ap_station` drains
actual DMA plus firmware token owners, then requires BASIC disconnect/WTBL reset
before returning a WCID to the pool. A dropped delete retains its peer, key,
closed capture and control reservation until verified cleanup. Errors after
publication retain a failed/quarantined owner until verified recovery.

`add_ap_key`, `delete_ap_key` and `default_ap_key` operate on the software-CCMP
owner after packet dual retirement. Secret staging precedes construction of the
async future, including unpolled cancellation. No WTBL encryption key is installed
in this fresh-reset AP generation. Group installation does not implicitly select
a transmit GTK; SET_KEY must select an installed slot, and deleting that slot
does not select another. PTK deletion closes its peer port. Identical current
material preserves all counters; retired material is refused before changing
the live BSS. Verified reset clears active slots while retaining the bounded
zeroizing material history, so deleted keys cannot receive a new nonce space.

`step_ap_network` retains native peer WCIDs and real software-encrypted FromDS
frames until both packet receipts retire. The raw ToDS decoder rejects hardware
decrypted plaintext, foreign WCID/channel, translated/fragmented frames and
malformed crypto metadata. It requires the actual peer association, host port,
current-key MIC and per-TID replay state before ordinary Ethernet delivery.
Capture binding is distinct from the per-peer port: every peer/key/port change
renews the global copy epoch. An earlier copy cannot inherit later admission.
EAPOL remains excluded from ordinary data rings. Final delivery must recheck
the returned copy epoch/current completed interface identity after unlocked
callbacks. Completed BSS ownership survives closing the old request socket;
it never survives mode, DOWN, namespace or interface-rebind identity changes.
`transmit_ap_management` retains the current actual request across packet
drain and transmission. An associated destination uses its peer WCID; an
unassociated destination uses the configured vif BMC WCID19, matching
`mt792x_tx`. Unicast requests a native HOST TXS PID. Positive ACK requires the
matching PID/WCID/TID/format report plus both native packet receipts; TX_FREE
alone cannot invent it. A failed terminal report returns false, and multicast
never claims a peer ACK. Ambiguous/malformed or missing receipts quarantine the
owner until verified reset. Terminal TXS PID reuse follows Linux's once-only
`idr_remove` report ownership, after packet dual retirement; cancellation does
not make an uncertain report eligible for reuse.

`update_ap_station` initially permits host authorization with unchanged native
legacy peer parameters. It waits for already-published packet dual retirement,
renews the copy epoch and never resets WTBL/native sequence for a port-only
change. The synchronous helper refuses outstanding packets. `update_ap_beacon`
preserves attribute absence, validates the complete new template/profile before
publication and retains an uncertain `pending_plan` until the real beacon ACK
or verified reset. The current profile preserves installed rates/RF/MAC slot
timing; an incompatible replacement is refused before native writes.

Native RX also produces bounded `ApRxEvent` records for actual unprotected

### Native CNM capability and protocol preparation

retained from that immutable WM artifact. It follows the actual region-length

and neither promotes a chip/role nor supplies a loaded-firmware/RF grant. Legacy

regulatory policy and exact CNM token/channel grant.

### Retained active scan

`Transport::scan_active(channels, ssids)` and
`firmware_transport::scan_boot_active` use the same retained VIF/MCU/RX owner as
passive scans. The public facade advertises four scan SSIDs, matching Linux
`mt792x_init_wiphy`. A nonempty list of up to four 0–32-byte SSIDs selects active
scanning; empty entries request a wildcard probe. Nonempty entries are packed
with Linux's specified-only SSID semantics; two probes per SSID are requested.
The facade normalizes an explicit active request without SSID entries to one
wildcard entry. The complete 1186-byte v1 request, binary SSIDs, wildcard and 39-channel
extension layout are checked against fixed wire vectors in `scan_reference.bytes`.
Historical source/output hashes are retained as provenance. Native Rust tests
exercise the real MCU/transport owner; no source extraction or C/Python compiler
workflow is maintained. These fixtures are not firmware or physical RF evidence.

`scan_active_with_ies(channels, ssids, extra_ies)` and
`scan_boot_active_with_ies` extend the same retained path with complete optional
Probe Request elements. The public facade reports the native600-byte budget.
The packed request retains1186 bytes: length is LE16 at224 and copied IE
content occupies226..826, before the v1 extension. Malformed extents,
truncated vendor/extension elements, oversized content and firmware-owned
SSID/Supported Rates/Extended Rates elements fail before scan setup writes.
Passive probe IEs remain invalid. Opaque probe content grants no association,
PHY, key or controlled-port authority. Existing no-IE APIs retain identical
wire bytes. Native600-byte, preflight, all-publication cancellation and active
scan→VHT/RX2 DHCP/IP vectors pass in the coordinated software suites.

`ScanOptions` and `scan_with_options`/`scan_boot_with_options` additionally
carry a per-request randomized source-address/mask pair for active or passive
scans. The family source advertises SCAN_RANDOM_MAC_ADDR. Like Linux
`get_random_mask_addr`, the native owner obtains fallible secure host entropy,
then resolves each byte as `(random & !mask) | (addr & mask)`. Firmware receives
that resolved address at1116..1122 with SCAN_FUNC_RANDOM_MAC bit0 alongside
split-scan bit5; it receives no mask and supplies no invented entropy proof.
The mask must fix the unicast bit and the supplied address must be unicast.
Malformed options, absent active RF authority, incompatible state/band and
entropy failure precede any scan publication or sequence/state consumption.
Passive randomization preserves NO_IR and never enables probes. The radio's
station identity remains unchanged, and an ordinary subsequent request clears
the random flag/address. Cancellation retains the same uncertain native owner.
Literal mask/address, entropy/authority/cancellation and randomized active-scan
to actual original-MAC Open/WPA2 DHCP/IP vectors pass in those suites.

Active admission requires the current authenticated host policy. Every selected
20 MHz channel needs full rule coverage and representable signed half-dBm power;
any overlapping DFS, NO_IR or narrower-bandwidth restriction denies TX, and the
lowest overlapping ceiling wins. Explicit prohibited channels fail before any
hardware/recovery writes. An implicit channel list is filtered to eligible
channels on actual firmware-reported bands and fails if none remain. Passive
receive geometry remains available without active permission. Associated active
and off-channel scans retain the station owner as described below. Explicit
dwell-time control remains unsupported; colocated six-GHz selection uses the
split scan path described later in §3.

Requested scan dwell control is inapplicable to this CONNAC2 owner (resolved,
see §8 "Applicability resolutions"). Linux `mt76_connac_mcu_hw_scan`
(mt76_connac_mcu.c:1853) sets `duration = is_connac2(dev) ? 0 : ...` and writes
that zero into the timeout/minimum/dwell fields regardless of the requested
`sreq->duration`; `is_connac2` covers 0x7961/0x7922/0x7920/0x7902. The shared
mt792x registration of `NL80211_EXT_FEATURE_SET_SCAN_DWELL` (mt792x_core.c:824)
therefore never reaches CONNAC2 firmware, and the native facade keeps rejecting
an explicit duration with `NotSupported` instead of silently ignoring it.

Before `START_HW_SCAN`, the owner first retains/reserves its running state,
prepares the unassociated NO_IR VIF if needed, and programs each selected
channel's host rate-power ceiling. The 2.4-GHz then 5-GHz ordering is independent
of scan channel order; the final SKU
row alone carries the global terminal marker. That band ordering is checked
against the unchanged Linux `mt76_connac_mcu_set_rate_txpower` with both requested
channel orders in the native transport regression. Every SKU message is followed by Linux's
correlated `REG_READ(PSE_BASE=0x820c8000)` barrier; the event kind, exact extent
and register identity must match. Only then is a legacy20 domain permitting
the selected channels published. Host country/channel/power permission is
rechecked between stages, immediately before the probe-producing scan command
and on each bounded receive poll. Firmware EFUSE/CLC limits remain in effect;
no measured board data or country authority is synthesized.

Successful scan completion must match the nonzero seven-bit scan sequence.
An unassociated owner restores its NO_IR-only idle domain before returning
ScanReady, so a later passive scan does not inherit probe authority. Native probe responses
share the bounded checked beacon parser/cache. A policy denial, malformed PSE
reply, hardware revocation, timeout or other failure makes the attempt terminal;
scan cancellation and domain closure are attempted when authority/ownership
permit, but neither command DMA receipt proves firmware idle or releases DMA.
Dropping a waiter at power/PSE/domain/start/idle-domain publication or during
the scan leaves Running and rejects replay until verified reset/reload. The
existing retained recovery worker handles that generation boundary. Native
regressions cover those publication points, stale completion refusal, policy
change before probes and during receive, exact power/domain sequencing, and
passive continuation. Live regulatory-source revocation is still bounded by the
shared cached-domain contract; current PCI authority is invoked at native I/O.

### Associated and off-channel scans

`Mt76Iface::scan`, the retained boot scan entrypoints and `Transport` accept
active or passive scans while associated, preserving the original peer/AID,
security owner, receive epoch and BA agreements. Firmware performs the split
off-channel dwell and returns to the operating channel; no new association or
invented scan-idle receipt is used. Associated random-MAC requests return Busy
before hardware writes. Pending key/control work is serviced before admission.

An associated active scan includes the exact occupied-channel SKU rows in its
power batch, with stable 2.4/5/6-GHz ordering and only the final row marked
`last_msg`. A probe row overlapping an operating constituent is capped at the
operating grant's power, so 20-MHz scan limits cannot raise a wider link's
ceiling. The temporary channel domain retains every operating constituent and
its width alongside the admitted probe channels. After the matching scan-done
event, the owner replays all occupied-width SKU rows through a correlated PSE
read, then restores its operating channel domain. Other channels remain NO_IR.
Station and scan policy are checked throughout those operations.

The scan collector hands original copy-time `CapturedData` records from the
operating channel to the production station parser through a bounded native
queue. Off-channel observations stay in the scan cache. Ordinary data,
EAPOL, ADDBA/DELBA, SA Query, peer closure and WMM/PHY changes therefore keep
their normal validation. Each bounded poll advances TX DMA/free retirement,
RX reorder timers and retained key/control work. Up to64 validated Ethernet
frames wait for scan completion; a rekey invalidates frames from the older
receive epoch before any publication. Pending data keeps its original token
and terminal-receipt ownership across the dwell.

Failure closes station/key/epoch authority before best-effort cancel/domain
cleanup can await. It leaves a terminal owner requiring verified recovery;
ambiguous or cancelled scans retain their running DMA owner and cannot replay
or restore an associated producer. Software regressions under
`drivers/wireless/mt7921/scan` cover linked HT40 Open/WPA2 data and BA during
an off-channel scan, exact power/domain restoration, pending TX plus rekey,
peer closure, random-MAC refusal and cancellation. Dated software validation
(2026-10-29): these scan tests passed the x86_64 r10 affected-scope run and
both aarch64 r9 (371 pass/0 fail/2 hardware skips across its selected scopes)
and aarch64 r10 broad run (2689 pass/0 fail/5 hardware skips, excluding only
the separately retested tx_ba group). Associated/off-channel scan software
scope is closed; these results do not establish RF or real firmware scanning
on silicon.

MT7920 selects `MT7920_FIRMWARE_WM`
(`mediatek/WIFI_RAM_CODE_MT7961_1a.bin`) with
`mediatek/WIFI_MT7961_patch_mcu_1a_2_hdr.bin`. MT7921 uses the distinct
`MT7961_FIRMWARE_WM` (`WIFI_RAM_CODE_MT7961_1.bin`) and `1_2` patch;
MT7922 uses its MT7922 RAM/patch pair. These pairs follow Linux mt7921's

`Mt76Iface` implements `WirelessNetIface` for legacy 20 MHz 2.4/5 GHz channels and has live
Open/WPA2 station dispatch and retained packet service. It derives frame-registry
authority, registers a real kernel transmit callback, delivers RX to the kernel
and IPC rings, and drives bounded DMA progress from executor and synchronous
network waiters. The station contract includes peer-bound RSNA, UNI3 key updates,
BMC WTBL/GTK setup, hardware CCMP replay windows and acknowledged disconnect.

(`STA_REC_MURU` is18). The key TLV copies Linux `enum set_key_cmd` directly:

### Negotiated WMM prerequisite

A scan BSS with one valid WMM v1 Parameter IE selects an automatic, restricted
WMM station profile. All four distinct ACIs, AIFSN/CW geometry, reserved bits
and complete IE extents are validated before any device writes. BE admission
control is rejected because there is no TSPEC owner. An Information IE alone
does not supply contention parameters and retains the normal legacy profile.
Caller-supplied WMM/HT IEs remain rejected by the common SME guard; the driver
appends its own WMM Information IE with U-APSD and service-period bits clear.

After the common association response binds the peer, status, AID and legacy
rates, the driver requires a valid WMM Parameter IE in that response. Missing,
duplicate or malformed parameters terminate the attempt before EDCA or a QoS
peer is published. A valid updated response parameter set replaces the scan
copy. A non-WMM scan profile retains non-QoS legacy behavior even if the AP
response contains unsolicited WMM parameters.

The retained owner emits Linux CONNAC2 CE `SET_EDCA_PARMS` (0x1d), with four
ten-byte rows in BE/BK/VI/VO ACI order and BSS/WMM set zero. CW values use
`(1 << ECW) - 1`; TXOP values retain their 32-us units. Every row carries the
AP's own parameters, exactly as `mt7921_mcu_set_tx` (the ACM bit is not part of
the firmware row; host admission control is applied by priority downgrade). A
matching, exact-size MCU PSE register read bounds command progress before
associated BSS_INFO_QBSS (tag 15), STA_REC_BASIC and WTBL_GENERIC QoS bits
are published. This is an
ordered native command path, not a fabricated EDCA acceptance event.

Only a fully associated Open or completed WPA2 controlled port enables QoS
Ethernet TX. Each frame's 802.1D user priority follows
`cfg80211_classify8021d` (RFC 8325 DSCP table for IPv4/IPv6, MPLS TC, 802.21
network control; no QoS Map or out-of-band VLAN tag exists natively) and
`ieee80211_downgrade_queue` (VO->VI->BE->BK while the AP's WMM ACM bit marks the
AC; `wmm_acm` per-UP bits as `_ieee80211_sta_wmm_params`). The TXD carries the
TID in TXD1[22:20] and `Q_IDX = mt76_connac_lmac_mapping(ieee802_1d_to_ac[tid])`
with native QoS DATA subtype fields in TXD2/TXD7 (`tx_priority.rs`,
`packet_tx::ethernet_tid`). TID 0 keeps the BE paths, including the TID0-only
originator BA; other TIDs carry BA_DISABLE. The installed PTK protects every
TID (firmware owns the per-TID CCMP PN); native QoS RX retains separate per-TID
CCMP replay windows; descriptor, token and payload retirement still require
both DMA and firmware completion. No U-APSD, TSPEC or QoS Null is enabled; BE
admission control remains rejected (no TSPEC owner). Evidence:
`mt76_wmm_classifies_all_user_priorities_onto_lmac_queues_and_downgrades_acm`. The separate negotiated HT20
profile below can additionally admit HT rates and bounded A-MSDU RX.

Station power setup now drains the host SKU command through the same correlated
PSE read used for active scans before any management TX. Association admission,
EDCA programming, terminal association and each management/Ethernet submission
recheck current PCI authority and signed host country/channel permission. A
country change, restrictive overlap or lower power ceiling cannot reuse the
earlier programmed grant. Each station BSS/peer/controlled-port/PTK/GTK command
checks permission before publication and after its matching receipt, and rekey
checks again before restoring Associated. Losing live permission clears the
host WMM/security/grant and makes the station terminal; explicit policy
reinstallation requires verified recovery and a fresh join. Receive-only policy
remains independent of TX.

A bound AP beacon/probe response with a valid changed four-bit WMM Parameter
Set Count now queues one owned contention update. Counter15→0 is a change,
exact repeats do not post commands, and successive received updates coalesce
to the latest complete set. Source MAC, BSSID, destination, native channel,
integrity and unfragmented management format must match the current station.
An unsolicited WMM IE cannot promote a non-WMM peer. Missing/malformed
parameters or changed contention rows with an unchanged counter still close
the connection until a fresh join.

Queuing an update blocks new DATA immediately while already-submitted native
tokens drain through both completion proofs. The retained control owner then
leaves Associated before its first wait, emits the same no-reply44-byte CE
`SET_EDCA_PARMS` body and checks the matching exact-size PSE read before
publishing the new set and restoring Associated. Current PCI and host
channel/power permission are checked before and after the native waits.
No peer/key reinstall, BA reset or PN/receive-epoch reset is performed for a
contention update. BE retains the conservative AIFS/CW/TXOP clamps above.
Pending key work runs first; an EDCA update cannot bypass a closed RSNA port.
Native Rust cases cover held DATA, literal native commands, counter wrap and
coalescing, Open/WPA2 per-TID replay, DMA/PSE cancellation, malformed progress,
policy loss, foreign/legacy beacons and actual replacement key receipts.
The existing WMM DHCP/IP compositions additionally perform a bound AP update
with their real negotiated PHY and BA owners before acquiring the lease.
These cases passed in the coordinated Wi-Fi suites: x86_64 2360 pass,0 fail,
9 skip; aarch64 1890 pass,0 fail,3 skip. Both production boots and btrfs
postflights were clean. These are scoped software totals, not physical RF proof.

Rekey retains negotiated WMM while its existing running state blocks ordinary
packets. Teardown retires host WMM/security/TX permission and pending EDCA
updates before its first wait; only a local one-shot permission can authorize the closing
deauth after a fresh policy/capability check. It removes keys/peers and restores BSS
QBSS/EDCA QoS zero before reusing the idle radio; verified reset clears all negotiation.
Cancellation or ambiguous EDCA/PSE completion retains the running/failed owner
and DMA until verified recovery, with no authorized station publication.

Native Rust smokes under `drivers/wireless/mt7921/wmm` exercise literal
EDCA/TXD wire fields, negotiation and response binding, malformed/downgraded AP
responses, current policy, per-TID replay, parameter changes, cancellation and

### Bounded recipient RX BA and sequence reordering

`Session` accepts an immediate compressed recipient BA agreement only after a
genuine HT/WMM Open or WPA2 association. A native ADDBA request must bind the
current AP, station, channel and WCID1; unfragmented action framing, dialog,
TID, starting sequence, requested window and timeout remain attached to the
one pending transaction. The retained firmware's one-octet BA-enable bitmap
bounds this profile to TIDs0–7. The negotiated window is the exact requested
size up to the peer's `max_buf_size`: 64, or 256 for a negotiated HE peer (see
the HE profile). This includes non-power-of-two values, and zero selects that
bound. Linux mac80211 `__ieee80211_start_rx_ba_session` (net/mac80211/agg-rx.c:337–357
in 7.3-rc7) declines `buf_size > max_buf_size` with
`WLAN_STATUS_INVALID_QOS_PARAM` (38) and an immediate-policy response. The
native owner does the same and sends no WTBL_BA/STA_REC_BA programming
(`rx_ba::Request::oversize`); earlier rounds clamped such requests instead.
Only after that check does mac80211 clamp to the driver's
`max_rx_aggregation_subframes` (agg-rx.c:362–364; mt792x: 256, which is never
smaller than the bound). CONNAC2 WTBL/STA records
carry that16-bit window directly; CONNAC1's discrete window index does not
apply. Independent exact-SN host slots avoid modulo-window aliasing across
4095→0. Delayed BA, unsupported
windows, fragmented starting sequences, unsupported TIDs and incompatible
active-TID replacement requests are explicitly declined. Identical pending
requests cannot duplicate setup, while active retries resend the same response
without resetting native sequence or replay state. Response backpressure never
changes an already accepted identical request into a contradictory decline.

Source `mt7921_mcu_uni_rx_ba` calls `mt76_connac_mcu_sta_ba`: the owner first
submits unified STA_REC_UPDATE with WTBL_SET/WTBL_BA, recipient type2, actual
peer/TID, MAC-and-TID reset and window. A second command supplies STA_REC_BA,
the actual SSN/window and TID enable bit. Both must earn exact matching native
receipts. Only then may a successful ADDBA response be transmitted. The host
recipient activates only after that response's native management completion
and fresh current full-channel/power/device permission. No requested flag or
command submission alone activates reception. Setup cancellation retains its
reserved native record in the running station owner; rejection or authority
failure becomes terminal and retains published DMA/uncertain firmware state.

Normal RX now retains native WCID and TID alongside the existing cipher,
integrity, channel and A-MPDU fields. An active agreement requires WCID1 and
agreement TID to agree with the current peer's untranslated QoS MAC header.
The supported ACK-policy forms are normal/immediate-BA data; unsupported
header/control/fragment forms cannot enter the window. Twelve-bit sequence
comparison and bounded per-TID buffers handle wrap, duplicates, forward-window
movement, compressed single-TID BAR and holes. All release/advance loops are
bounded by the negotiated window. Source reorder-hole timers are100ms for
TIDs0–3 and40ms for TIDs4–7. A nonzero negotiated inactivity timeout is tracked
in1024-us units and queues recipient DELBA/native retirement. Timer progress
uses the existing bounded network/control poller.

CCMP integrity/peer/key-index/native metadata are checked before buffering;
duplicate queued PNs cannot occupy a second slot. Packet-number commitment
follows sequence release, as Linux performs `mt76_check_ccmp_pn` after
`mt76_rx_aggr_reorder`. Each released MPDU rechecks the current per-TID replay
floor before data or bound EAPOL delivery. A-MSDU first/middle/last bursts on
that TID share the reorder owner, preserving one PN for the complete checked
MPDU and its atomic subframe group. A genuine ADDBA request offering A-MSDU
support can now negotiate that bit in both native STA_REC_BA and the acknowledged
response. Only that active agreement admits native A-MSDU-in-A-MPDU; a request
without the bit retains the prior denial and standalone A-MSDU fallback.
BlockAck-policy aggregates additionally require the live BA owner.

Every piece must retain the same original MAC header, key/PN, WCID, native TID
and A-MPDU classification through completion. PHY/integrity/native extent errors
discard the partial original. Source first/middle/last and two-byte hardware
padding rules feed a bounded logical plaintext aggregate, with only opaque
inter-subframe alignment reconstructed when hardware omitted it. The shared
whole-aggregate decoder checks all original subframes, including VLAN-wrapped
control-port denial and nonlocal source addresses, before any output or PN
commit. A complete MPDU enters the BA SN window before its sole PN commitment.
No partial subframe group can cross a malformed suffix, DELBA or key epoch.
This follows mt76's native assembly-before-reorder/completion order.
Recipient negotiation never
changes TXD3.BA_DISABLE or enables a TX originator/retry queue; the independent
originator transaction below owns transmit eligibility.

Peer DELBA/inactivity closes queued host delivery before native waits. WTBL_BA
reset/window-zero and STA_REC_BA disable must both complete before the record
can be replaced. Rekey and disconnect fence every host reorder/ready packet
before the first retirement wait, then retire all native receive-BA records
before PTK/GTK or WCID reuse. Key epochs cannot carry queued PN/sequence state
into a replacement agreement. Cleanup remains available without RF permission,
but its native receipts/device authority are mandatory; an optional outbound
DELBA still needs current TX permission. Cancellation cannot restore an
associated producer or free uncertain mappings. Peer loss, policy failure and
shutdown close delivery; verified reset clears old records only after the
existing quiescence/release/recycle proof.

Ten native Rust smokes under `drivers/wireless/mt7921/rx_ba` cover literal
WTBL/STA/response bytes and ordering on HT20/HT40 in both bands, Open/WPA2,
wrap/forward windows/BAR/hole/inactivity timers, repeated and declined requests,
native WCID/TID/integrity/replay and nested-aggregate denials, ordinary A-MSDU
composition, actual EAPOL rekey/key receipts, reset, every policy/publication
boundary, native rejection and setup/response/rekey/teardown cancellation.

Two compose real recipient negotiation and A-MPDU-marked native RX through

### Native transmit queue and per-packet ownership

A genuine negotiated HT/WMM station can now keep up to eight independent
Ethernet MPDUs outstanding in the retained16-slot WFDMA data ring. This is a
native packet/ownership feature. Before an originator agreement, every packet
retains TXD3.BA_DISABLE; hardware TX A-MSDU follows `wcid->amsdu` (above).
Legacy/non-HT profiles retain their
one-frame path. An ordinary per-frame transmit future starts only on an empty
queue, so another producer's completion cannot satisfy that future.

Each submission retains its own native token, physical descriptor slot and
payload until both WFDMA DIDX/DDONE and that token's firmware TX-free status
are terminal. The producer advances on publication; an independent DMA cursor
checks only a submitted prefix, including wrap. Slot ownership and an eight
frame limit below the ring depth prevent full/empty aliasing or reuse of a
payload still held by firmware. A newer TX-free report cannot free an older
unconsumed descriptor. Firmware records may arrive out of order; software
retires the submitted FIFO only after both proofs for its head. The entire
native release event is checked for contradictory owned-token statuses before
any status is committed. Foreign tokens cannot complete an owned payload.

Every queued frame earns current device/channel/power admission separately.
Pending EAPOL/rekey or receive/transmit-BA control stops replenishment, drains all old
packet receipts and then runs the control owner. Keys/WCID cannot be removed
after only the first queued completion. A rejected packet or malformed/expired
native completion closes host security/grant/producer state while retaining
the uncertain tail. Oldest-packet deadlines cannot be refreshed by later
submissions. Cancelling teardown retains the running owner and every queued
packet; late terminal receipts do not restore association. Only verified
reset/quiescence/release/recycle clears an uncertain generation.

Eight native Rust smokes under `drivers/wireless/mt7921/tx_pipeline` cover
actual coherent descriptor/doorbell/ring wrap and split/out-of-order DMA/free
proofs, invalid prefixes, whole-event atomicity and per-packet statuses;
genuine Open/WPA2 HT/WMM admission and legacy fallback; bounded refill,
per-publication policy loss, terminal failures/timeouts, authenticated rekey
priority and cancelled teardown/reset. These do not establish RF acceptance.

### Fresh-peer per-TID originator TX BA

`Transport::associate_station` now attempts immediate HT originator BA after
genuine HT/WMM association and Open/WPA2 controlled-port completion, before
carrier or the first QoS Ethernet MPDU. The explicit
`Transport::negotiate_transmit_ba() -> Result<bool, Error>` entry uses the same
owner; `transmit_ba_active()` reports its current retained association state,
not transmit authority. `negotiate_transmit_ba_tid(tid)` exposes the same
protocol for each TID0–7, and `transmit_ba_tid_active(tid)` reports that TID's
completed agreement. Legacy and non-HT profiles return false; TIDs8–15 are
refused. The registered radio exposes this control as the concrete
`Mt76Iface::negotiate_transmit_ba_tid`, which serializes with the interface
control mutex and invokes `negotiate_boot_transmit_ba_tid` on the retained
boot `Transport`; no caller needs access to the private boot-owner mutex.
Midstream entry after an Ethernet or fragmented-MSDU publication on
the requested TID returns Busy without writes: the current native hardware
sequence is not guessed or reset. Traffic on one TID does not consume
another TID's fresh sequence or dialog domain. Midstream callers use the
separate retained sample/restart control below.

The retained profile is immediate compressed BA independently for TIDs0–7 on the
existing2.4/5GHz HT20/HT40/SGI Open/WPA2 station. Before request publication it
stops producers and requires an empty native packet queue. It sends a genuine
ADDBA Action with a non-reused nonzero dialog, A-MSDU capability, timeout0, HT request
window64 and fresh-per-TID request SSN0. The HT window64 follows mac80211's
documented compatibility workaround. Non-QoS MLME/EAPOL does not consume this
QoS sequence domain. An actual native unfragmented response must bind WCID1,
current channel, AP transmitter/BSSID, local receiver, dialog and requested TID;
the immediate policy and a nonzero window no larger than64 are required;
the responder's A-MSDU-in-A-MPDU bit is retained.
Response timeout is bounded by both elapsed time and poll count. Foreign,
late, duplicate or unaccepted responses cannot activate the owner. Dialog
exhaustion leaves a fresh peer on clean non-BA fallback rather than reusing a
token that an old native RX could name.

After positive request transmission and an accepted response, the owner
submits unified STA_REC_UPDATE containing WTBL_SET/WTBL_BA, originator type1,
then a second command containing STA_REC_BA, originator type1, the requested
TID and its `enable << tid` bit.
Both exact native receipts and current station permission before/after each
command are required. Native operational SN0 follows mac80211's
TX_OPERATIONAL callback; it is distinct from the ADDBA request SSN and is not
a general midstream sequence readback. Window is the accepted response value,
and recipient-only fields remain zero; STA_REC_BA carries the accepted
A-MSDU bit. There is no CONNAC1-only window
index, host SN_VALID, invented current rate or host CCMP PN. The source
contracts are `mt7921_ampdu_action`, `mt7921_mcu_uni_tx_ba`,
`mt76_connac_mcu_sta_ba`, its WTBL/STA BA helpers, and
`mac80211/agg-tx.c`'s request/operational/stop continuations.

Control waits may collect AP closure, changed HT/WMM facts, peer DELBA or a
new authenticated key challenge. The existing production receive parsers run
through an actual native RX idle observation before activation becomes usable;
an empty decoded-frame result is insufficient. No associated producer is
published over those awaits. Only this completed owner selects Ethernet
TXD3.BA_DISABLE0 for its own TID. Native QoS/TID/AC selection,
firmware rate/sequence/retry/CCMP and
per-MSDU token ownership remain intact; TX A-MSDU follows the responder's
A-MSDU bit. Outstanding packets
are conservatively bounded by min(8, every active agreement's accepted
window) across the shared packet pipeline. Both native DMA and firmware TX-free
proofs still retire every MSDU separately; a host aggregate-success flag cannot
replace either proof.

Explicit refusal preserves clean non-BA fallback. Unsupported positive offers
or no response require positive local DELBA transmission before abandoning
possible peer agreement. Native setup failure, ambiguous management completion,
authority loss or cancellation retains Running/Failed ownership and uncertain
remote/native records; it cannot be relabeled fallback success. Peer DELBA or
the response's nonzero inactivity timeout stops replenishment, drains all old
packets, and requires WTBL then STA disable receipts with zero enable/window.
A local stop sends DELBA only afterward under current RF permission. Rekey
retires both TX and RX BA before M2/PTK/GTK publication; disconnect retires both
before key/WCID removal and uses its separately checked closing deauth grant.
Verified reset clears uncertain records only after quiescence/release/recycle.
Late receipts cannot restore a cancelled associated producer. Clean fallback
remains non-BA for that TID until an explicit, freshly sampled native
restart; the fresh-only entry never guesses that used sequence.
Each TID retains its own response timeout, inactivity state, non-reused
dialog inventory, native WTBL/STA ownership and A-MSDU response bit. A peer
DELBA or failed offer retires only the named TID. Rekey/disconnect/reset
fence and retire every native originator before any key or WCID reuse.

Native Rust smokes under `drivers/wireless/mt7921/tx_ba` cover literal
ADDBA/WTBL/STA enable/disable order in both bands and widths with Open/WPA2,
bound/invalid/refused/missing responses, small windows, inactivity, native
rejection, publication authority loss, every setup cancellation boundary,
RX idle with data ahead of peer closure, both-role rekey/key receipts and
teardown/reset. One exercises actual coherent TXD/doorbell/token/DMA/free
ownership with BA eligibility and no A-MSDU. Two compose actual originator
negotiation/native records, production packet encoders and Open HT20 or WPA2
HT40 (both BA roles) through DHCP and exact bidirectional IP. Existing HT/WMM
DHCP profiles now also exercise genuine no-offer request/DELBA fallback before
carrier. Native software tests establish control/packet ownership, not real
firmware execution or RF aggregation/interoperability.

### Midstream originator BA restart and native TXS sequence ownership

`Mt76Iface::request_transmit_ba_restart_tid(tid)` serializes with the production
interface control mutex and calls `request_boot_transmit_ba_restart_tid` on
the retained boot radio; `Transport` exposes the same operation. A request
requires a real associated HT/WMM station, current RF/security permission,
TID0–7 and no older pending packets/fragments/control work. The native backend
independently requires its packet-token queue empty: every older firmware/MAC
TX MSDU must already have both DMA and TX_FREE terminal receipts. The selected
old originator is retired with WTBL/STA disable receipts and DELBA before a
new sequence sample is admitted. Other TIDs' agreements remain independent.

The request queues a retained sample intent. It sends no QoS Null, fabricated
probe or other extra RF packet and does not await another executor task for
traffic which does not yet exist. The next actual user MSDU on the TID (or
its final real fragment, after every predecessor's terminal proof) receives
TXD5.HOST_TXS plus an owned PID. Exactly that MPDU clears HW_AMSDU and stays
outside BA, matching `mt76_connac_mac.c:579–587`; ordinary user packets retain
their A-MSDU eligibility. Further same-TID publication is fenced until the
sample and restart resolve. Other TIDs can progress. The async Ethernet
wrapper now drains every fragment's native terminal receipt before reporting
the whole MSDU complete. These are normal hardware-auto-sequenced
fragments: TXD3.SN_VALID remains clear. Linux sets that manual sequence
control only inside `IEEE80211_TX_CTL_INJECTED`
(`mt76_connac_mac.c:477–490`); the sampled path is never injected.

The native RX router decodes PKT_TYPE_TXS as its two-dword header plus complete
eight-dword records (`mt7921/mac.c`). The retained sample binds PID, WCID1,
TID and MPDU status format; malformed/conflicting/aggregate/error status
cannot yield a sequence. TXS1.SEQNO is accepted only together with the exact
sample token's DMA+TX_FREE terminal proof, in either arrival order. Neither a
host MSDU count nor one native receipt substitutes for the missing proof.
ADDBA uses `(observed SN + 1) & 4095`, including wrap. The source-required
management TXD.ADD_BA and actual TID are encoded. Linux's distinct
TX_OPERATIONAL WTBL BA SN stays0 (`agg-tx.c:762–765`); no host SN_VALID or
sequence-counter reset is introduced. Both native enable receipts and the
bound peer response remain necessary before the target TID aggregates again.

PID ownership follows Linux `tx.c`'s `idr_remove` terminal HOST-MPDU-TXS
contract plus `__mt76_tx_status_skb_done`'s receipt conjunction. The operating
source assumption is one terminal MPDU status per requested PID, as that
upstream ownership relies on; duplicate identical records before retirement
are idempotent. PIDs3–126 (mt76's seven-bit ID mask, excluding reserved/rate
IDs and the exclusive upper bound) can be recycled only after matched TXS
and native packet terminal receipts. A published cancellation, missing report,
conflicting metadata or timeout quarantines the PID; elapsed time and a
DMA-only reinit never free that ambiguity. Quarantined IDs clear only after
tracked WFSYS assert/release/ready, DMA idle, bus-master-off and clearing every
RX ring. Exhaustion refuses optional restart before changing the existing
agreement and preserves ordinary traffic. Native tests cover every report/
DMA/TX_FREE ordering, duplicate and foreign reports, PID reuse after exact
retirement, quarantine across DMA recycle, true final-fragment sampling and
literal descriptor fields.

The request is bound to its receive epoch. Rekey, disassociation and recovery
cancel its use of an old observation; native resources/PIDs follow their
separate retirement proofs. Missing/malformed status fails closed after a
bounded three-second wait from actual sample publication. Cancellation during
old-record retirement or ADDBA/native setup retains Running ownership. The
same explicit association/restore context used by associated scans preserves
their Running state through nested restart awaits. Synchronous network drains
can prepare and poll the retained key/control future themselves, so restart
progress requires native/self-waking receipts rather than another executor
task. MLME/RSNA composition regressions exercise Open/WPA2 and all TIDs, old
queued traffic, independent agreements, nonzero/wrapped sampled SNs, refusal,
missing/wrong reports, cancellation and full fragmented-MSDU completion.

Physical carrier is published with `net::iface::set_link_metadata` only after
association/security completes and cleared on teardown or failure. It preserves
operator `IFF_UP` independently and never invokes administrative open/stop hooks
while retained driver state is locked. Explicit registration/operator/autoconnect
changes remain administrative events. A carrier sample cannot undo operator DOWN;
physical disconnect preserves operator UP. Repeated publication of the same
state does not create new carrier transitions.

Initial and rekey nonce generation requires the fallible hardware-seeded
crypto adapter, requested only when a validated new M1 renews the SNonce.
Retries, M3 and group rekeys require no fresh sample. Entropy failure sends no
EAPOL reply, installs no key and
leaves the station outside the associated/authorized state. Deterministic
nonce sources exist only at the explicit private transport-model boundary.
The selected AP basic rate drives native authentication/association/EAPOL and
deauthentication TX, including OFDM-only APs. `associate_station_with_ies` checks
the SME security/PHY request and retains supported optional association IEs;
the interface validates frequency/channel consistency before recovery I/O.
`PacketStep`, `step_boot_network` and `service_boot_keys` define the bounded
packet/rekey progression described in the shared specification.

`Transport::prepare_ht20_receive(bss) -> Ht20ReceiveInfo` prepares an inactive,
bounded native receive prerequisite while the radio is idle. It validates the
actual firmware HT/band/NSS capability and singleton AP HT Capabilities/Operation
IEs for a one-stream HT20, long-GI receive envelope (MCS0–7, 3839-byte A-MSDU).
It makes no device writes, activates no peer or carrier, and cannot enable HT
association. A later association discards this preparation and constructs a new
receiver only from the genuine negotiated HT20 control path above.

The private post-admission receiver recognizes source-defined CONNAC2 RXD4
first/middle/last markers and removes the native two-byte header padding. It
stages every converted RFC1042 Ethernet-II subframe until the entire MPDU is
valid, with one matching peer/channel/header/TID/CCMP PN, a 100-ms age limit,
a 3839-byte aggregate envelope and the existing 16-descriptor receive budget.
Only complete bursts advance the pairwise per-TID replay window, once per MPDU;
no partial or malformed burst releases payload or consumes its PN. Foreign
unicast destinations, invalid source addresses, SNAP-as-destination injection,
EAPOL/preauthentication, unsupported cipher/header layouts and oversized
subframes discard the whole burst. Normal traffic, malformed descriptors,
rekey, peer loss, teardown and verified reset invalidate partial assembly;
queued delivery rechecks current backend authority. Fragmented A-MSDUs remain
absent (TX A-MSDU is the hardware offload above), and A-MSDU subframes stay RFC1042-only through the
shared `narf_wireless::amsdu::decode`. Production activation is restricted
to the complete negotiated HT20/HT40 path above.

Non-RFC1042 LLC receive is implemented for unfragmented native MPDUs.
`station_join::to_ethernet` follows Linux `ieee80211_data_to_8023_exthdr` /
`ieee80211_get_8023_tunnel_proto` (net/wireless/util.c) for a non-mesh,
non-A-MSDU station: RFC1042 SNAP (except AARP 0x80f3 and IPX 0x8137) and
802.1H bridge-tunnel SNAP (`aa aa 03 00 00 f8`) are replaced by their
EtherType; every other LLC body (AARP/IPX SNAP, foreign OUIs, plain 802.2 such
as STP) is delivered as an 802.3 length frame with its LLC header intact. Two
deliberate bounds are stricter than Linux: a tunnel header carrying a value
below 0x0600 stays length-framed instead of emitting an ambiguous type field,
and a length frame needs at least the three-byte 802.2 header and at most
`ETH_DATA_LEN` (1500) bytes. Length frames can never alias EAPOL, so the
existing controlled-port, protected-only and replay ordering is unchanged; a
discarded body still consumes no PN. `mt76_native_rx_delivers_non_rfc1042_llc_as_8023`
and the updated conversion/replay smokes in `firmware_transport_tests.rs` cover
it.

RX defragmentation is implemented for the associated station
(`rx_fragment.rs`, `Session::receive_fragment`). It follows Linux mac80211
`ieee80211_rx_h_defragment`/`ieee80211_reassemble_{add,find}`
(net/mac80211/rx.c:2292–2530) with the CONNAC2 delivery of
mt7921_mac_fill_rx (mt7921/mac.c:284): `MT_RXD2_NORMAL_FRAG` packets carry the
hardware-decrypted CCMP PN in RX group 1 and leave sequential-PN checks to the
host. `rx_native_with_amsdu` now exposes the FRAG marker (and rejects it with
hardware A-MSDU); `rx_native`, and therefore scan/auth/EAPOL parsing, never
admits it. The cache keeps four entries per station, replaced round-robin
(`IEEE80211_FRAGMENT_MAX`); a continuation must match sequence, replay queue
(QoS TID or non-QoS), frame type, addr1/addr2 and previous fragment number plus
one, and entries older than 2 s are purged on lookup. Multicast, ToDS,
HT-control, A-MPDU-flagged and fragmented-A-MSDU layouts drop, as does any RXD
FRAG/header disagreement. On a secure link every fragment must be
pairwise-key CCMP with PN above the current per-queue counter, continuations
need PN `last + 1`, and protected/plaintext mixing drops; only a complete MSDU
advances the counter, to its last PN. Linux's key-colour check is realized by
flushing the cache on every receive-epoch renewal (all PTK/GTK rekey and
association paths) and on teardown/invalidation. The reassembled MSDU is
bounded to 2304 bytes and then takes the normal `to_ethernet` path. Like
`ieee80211_rx_reorder_ampdu` (rx.c:1498), fragments bypass the BA reorder
buffer. A fragmented EAPOL PDU is never accepted on the controlled port, and
fragmented management frames are not reassembled. Smokes:
`mt76_rx_fragment_cache_follows_mac80211_reassembly_rules`,
`mt76_protected_rx_defragments_with_sequential_pn_and_replay` and
`mt76_fragment_descriptors_stay_out_of_management_paths`
(`rx_fragment_tests.rs`). TX fragmentation remains open: Linux mt792x only
fragments in mac80211 software once a wiphy fragmentation threshold is
configured (net/mac80211/tx.c:694, which also disables TX encapsulation offload
via iface.c:1118); NARF exposes no threshold configuration yet.

Fixed `amsdu_reference.bytes` data and historical source hashes describe
native RXD4 markers, padding and Ethernet conversion. Native Rust tests exercise
production descriptor parsing and bounded receive ownership directly; no C skb
adapter or extracted-source compiler workflow remains. `ht_receive` transport regressions cover
incomplete/malformed/replayed bursts, source geometry, bounds, timeout, current
authority and peer cleanup. Open/WPA2 DHCP/IP composition also exercises this
model-only receive seam after existing legacy MLME authorization. Those older
seam tests do not establish HT association or RF operation; separate negotiated
HT20 smokes now exercise its real control/activation owner.

`Transport::recover(expected_mac)` parks bus mastering, requests link ownership,
holds the WFSYS reset for 50 ms, waits for reset completion and proves DMA idle
before clearing hardware references and recycling owned rings/tokens. It reloads
firmware/radio state and requires the original MAC; it returns with carrier
closed and requires a fresh scan/association. `recover_boot_radio` owns the
reset future across caller cancellation. The interface tries at most three
automatic recoveries with backoff; an explicit scan/connect/disconnect can retry
after exhaustion. Initial firmware/radio failure uses the same retained reset
worker before any interface is registered.

### System suspend/resume and PCI removal/reprobe

`suspend_boot_radio` / `resume_boot_radio(expected_mac)` (and the interface
wrappers `iface::system_prepare_suspend` / `iface::system_resume`, bridged into
`narf_power::system_pm` by the `narf-drivers-wireless` facade as `"mt76"`)
follow Linux `mt7921_pci_suspend` / `mt7921_pci_resume`. Without WoWLAN,
cfg80211 `wiphy_suspend` leaves the BSS first (`cfg80211_leave_all`), so an
associated station is disassociated (locally generated DEAUTH_LEAVING) and
mac80211's interface removal/stop is reproduced natively: UNI BSS basic inactive,
UNI DEV inactive (`mt76_connac_mcu_uni_add_dev(.., false)` order) and EXT
`MAC_INIT_CTRL` disable. The PCIe handoff then takes driver own, turns the
radio LED off (EXT `ID_RADIO_ON_OFF_CTRL`), sends UNI `HIF_CTRL`
(`hif_type = 2`, `UNI_HIF_CTRL_BASIC`, suspend = 1, acknowledged as in
`set_hif_suspend(mdev, true, true)`), forces deep sleep (CE `CHIP_CONFIG`
`"KeepFullPwr 0"`), polls WFDMA idle, clears TX/RX DMA_EN, masks host interrupts and returns
LPCTL to firmware (ten 50 ms `HOST_OWN_SYNC` attempts). The radio is
`State::Suspended(info)`. A failed suspend runs the Linux restore path; if that
undo also fails the owner is `Failed{Suspend}` for verified reset.
Resume restores memory decoding (not bus mastering), takes driver own,
reinitializes WFDMA only when `MT_WFDMA_DUMMY_CR.NEED_REINIT` was lost (disable,
idle proof, unpublish, ring/token retirement, reprogram — `mt792x_wpdma_reinit_cond`),
otherwise re-enables bus mastering and DMA_EN on the retained rings, checks
firmware liveness, restores the native deep-sleep policy (`"KeepFullPwr 1"`),
reports HIF resume, reloads the package-selected CLC world limits
(`mt7921_mcu_regd_update`) and turns the radio LED back on. Any other failure falls back to the verified WFSYS reset with
the same identity (`mt792x_reset`); a revoked/gone device is `Failed{Resume}`
with its rings retained. Resume always returns an idle radio; the next scan
recreates the firmware VIF. Both transitions are retained across caller
cancellation.

The PCI remove hook (registered for every match name; Linux `mt7921_pci_remove`)
closes discovery, advances the binding generation, withdraws the interface from
the wireless, network and netdev registries (its worker exits), and retires the
transport synchronously: fence keys/BA/ports, stop DMA, bounded 100 ms idle
proof, unpublish rings. Bus mastering is always cleared; memory decoding is
cleared only after proven retirement. A transport busy in retained work or a
caller is retired by a reaper when returned. Every transport is stamped with the
generation it was claimed under: completed retained work of a removed generation
is retired, never republished (`admit_completed`), claims are refused for a
retired generation, and a claim is released only by its own generation. A probe
after the boot-time firmware initcall provisions itself with the same bounded
retry. Unproven retirement keeps the published rings forever, so a new
generation's freshly programmed rings can never alias them.

The legacy `full_bring_up` API remains side-effect-free `NotImplemented`
because it cannot retain the transport owner. The [shared specification](spec.md)
defines the exact firmware, station and receive contracts.

### Associated firmware-owned WoW handoff

`Mt76Iface` implements `wowlan_support`, `set_wowlan`, GTK-rekey admission
and the retained `suspend_boot_wowlan(config, SystemSleepState)` path.
Capabilities require the actual endpoint PM capability and a usable
`power::pci_wake::PciWake` route under existing device/platform grants.
Only a positive receipt is cached for stable capability reporting during
temporary native transport ownership. That report is not a grant: configuration
and the actual suspend handoff require fresh native route admission. A failed
resume keeps packet service parked until either resume or explicit verified
recovery completes; only successful reset may clear that parked state.
The delegated nl80211 interface administrator controls configuration.
Magic packets, disconnect/beacon loss and one 1–128-byte pattern at offset0
are admitted. NET_DETECT has its own associated/unassociated owner and
advertises ten probe SSIDs/matches, 512-byte probe IEs, 64 explicit frequencies,
one infinite plan up to65535seconds, delay and host-resolved random MAC.
Unsupported triggers, offsets, iterations and pattern metadata are refused.

Linux `mt76_connac_wowlan_support` (installed by `mt792x_load_firmware`)
advertises the following complete trigger/capability set:

| Linux advertisement | Native bounded profile |
| --- | --- |
| `WIPHY_WOWLAN_MAGIC_PKT` | Actual WOW_CTRL magic bit |
| `WIPHY_WOWLAN_DISCONNECT` | Actual disconnect and beacon-loss bits |
| `WIPHY_WOWLAN_SUPPORTS_GTK_REKEY` | Authenticated current CCMP-128 KEK/KCK/replay handoff; firmware rekey state retires through verified reset before fresh RSNA |
| `WIPHY_WOWLAN_NET_DETECT`, ten matches | Actual scheduled-scan request/enable and scan-hit bit, associated or unassociated |
| One pattern, minimum1, maximum128, default offset0 | Actual bitmap TLV with exact mask and bounds |

Linux does not advertise GTK-rekey-failure, any-packet, EAP-identity,
four-way-handshake, RF-kill or TCP wake for this owner; those triggers remain
unsupported here. Host-resolved NLO random MAC follows mt792x's existing
scheduled-scan random-address feature. This profile explicitly bounds probe
IEs to512bytes and NLO to one infinite plan,65535seconds and64 explicit
frequencies; it does not silently accept additional plans/iterations.

`system_prepare_suspend_for` preserves S0Idle versus S3 through the shared
async coordinator. The exact endpoint's `_S0W` or `_S3D`/`_S3W` constraints
are separate from an ancestor's `_PRW`. Native PCI D3hot requires actual
PMC support and that endpoint policy. Unsupported firmware power-resource/
`_PSx` sequences, non-byte GPE routes and missing SCI/platform authority
remain unavailable rather than assumed from the PCI ID.

The retained owner closes host carrier/rings and the receive epoch before
any wait, finishes already-owned user TX/fragments and pending control/key
work, then exports only current authenticated 16-byte KEK/KCK plus the
actual big-endian EAPOL replay counter in a zeroizing native request.
`SET_REKEY_OFFLOAD` can confirm those current keys, counter and optional AKM;
it cannot replace the driver's RSNA. Secret comparison is constant-time.
Every nested command/key wait retains a closed Running state. No artificial
packet is transmitted to force progress.

UNI OFFLOAD GTK-update/enable and empty-address ARP mode, UNI SUSPEND
MODE_SETTING/PATTERN/WOW_CTRL/GPIO requests are consumed through the real
MCU dispatcher before associated HIF suspend, deep sleep, DMA-idle/off and
firmware ownership. The firmware BSS/key context stays live for wake;
ordinary station RX/TX remains closed. No IP address is inferred from traffic.
The real PME/GPE owner is then armed before PMCSR D3hot. Each actual power
write retains its timestamp through cancellation; the mandatory PCI delay
precedes another configuration access. Native MMIO/config-command helpers
refuse the retained low-power interval. Unexpected synchronous owner loss
quarantines the actual wake route without attempting unsettled hardware I/O.

Resume restores D0, waits and verifies it, retires PME/GPE/firmware routing,
then performs verified WFSYS reset and ring/token/key/BA retirement before
any new host RX. Firmware GTK/IGTK updates are never reconstructed from an
unspecified event. Host association ends at prepare; a fresh scan/RSNA follows
resume. Only actual PME/GPE observations are retained, with no guessed
magic/pattern/SSID cause. Failure preserves closed ownership until cleanup
and reset receipts succeed.

NLO preserves an actual optional association; an unassociated owner never
invents a peer/channel/AID or key context. Its VIF setup and request use the
existing native scan controls. Directed probes require a current RF domain,
per-channel native SKU/PSE receipts and a matching allowed channel domain;
passive scans retain NO_IR, except a live association's occupied channel.
Operating-width power ceilings are never raised by a scan row. Six-GHz NLO
is passive only, matching the existing native discovery profile. Every
suspending command wait rechecks the retained RF snapshot before autonomous
scan enable. Firmware receives real channel identities, SSIDs, RSSI thresholds,
IEs, delay, interval and host RNG output. CE0x62/0x61 have native DMA receipts
and precede acknowledged WOW_CTRL START; separate firmware ACKs are not invented.
The default hardware channel list has Linux's64-entry clamp; oversized explicit
lists fail. Resume resets and retires the NLO generation before another scan.

The accepted pre-AP checkpoint executes all seven native WoW/NLO tests on
both x86_64 and aarch64 with zero failures, alongside shared PCI metadata/D-state,
PME/GPE and family-specific nl80211 NET_DETECT limits. Both-architecture release
production boots, postflight, Clippy and formatting gates pass for that checkpoint.
Physical wake/RF acceptance remains open. Nonempty ARP/NS table updates are a
separate optional continuation requiring actual address ownership; an empty table
supplies no invented address and does not grant an IP offload.

### WPA3-SAE and PMF

Implemented (Linux v7.2 `drivers/net/wireless/mediatek/mt76`,
`net/mac80211`; SAE itself is wpa_supplicant `sme_sae_auth` in Linux):

- `association::Security` gains `Wpa2PskPmf { psk, required }`
  (`ieee80211w=1/2`) and `Wpa3Sae { password }` (`sae_pwe=2`). Both prepare
  the shared plan with `JoinOptions::with_akms(AkmSet::ALL)` and, for WPA2,
  `with_pmf(Optional|Required)`; legacy `Wpa2Psk` keeps the default options
  byte-for-byte. `iface.rs` maps `SecurityConfig::Wpa3` to `Wpa3Sae`.
  `SecurityConfig::Wpa2` follows the supplicant's RSNE
  (`Security::wpa2_from_supplicant`). With no RSNE, or with PSK and no MFPC,
  it maps to legacy `Wpa2Psk`. Otherwise it maps to
  `Wpa2PskSelected { psk, akm, pmf }`, whose plan offers only that AKM (PSK
  or PSK-SHA256) under that `ieee80211w`, so the owner's RSNE repeats the
  supplicant's choice. MFPR without MFPC, or another AKM, is refused. The
  iface offers `supports_wpa2_mfp_offload`, `supports_optional_mfp` and
  `supports_psk_sha256_offload`, and `validate_join` admits the elements
  through `SmeRsna::Wpa2 { akm, mfp }`. Test:
  `mt7922_wpa2_pmf_and_psk_sha256_from_the_supplicants_selection` joins
  `FakeAp` with PMF required (PSK) and PMF optional (PSK-SHA256 on a
  PSK+PSK-SHA256 AP).
- SAE: `authenticate_sae` binds a boxed `SaeSession` (H2E or
  hunting-and-pecking, as the plan resolved), draws the Commit scalars from
  the device CSPRNG (`try_build_commit_with_entropy`), runs
  `JoinPlan::sae_authentication_response` through at most three
  anti-clogging retries and Confirm, and sends the PMKID-bearing request,
  extended with WMM Information and untyped HT Capabilities as the open/PSK
  request is. The SAE PMK feeds the retained supplicant with the plan's AKM
  (`JoinPlan::akm()`), the RSNXE in message 2/4 and `mgmt_group_key_len`.
- Keys: `MCU_CIPHER_AES_CCMP` is 5 (`enum mcu_cipher_type`); earlier records
  sent 6 (`MCU_CIPHER_CCMP_256`) for 16-byte CCMP keys, which is now fixed.
  The IGTK from message 3 or Group 1/2 is installed after the GTK on BMC
  WCID 19 as `mt7921_set_key(WLAN_CIPHER_SUITE_AES_CMAC)` →
  `mt76_connac_mcu_sta_key_tlv` sends it: one 80-octet `sta_rec_sec` with
  `n_cipher = 2`, `key[0]` = the stored CCMP group key and index (BIP
  batch `sta_key_conf`) and `key[1]` = `MCU_CIPHER_BIP_CMAC_128` with the
  IGTK. A PMF message 3 without an IGTK KDE fails the join.
- TX: `transmit_management` sets the Protected bit on every unicast robust
  frame (`_ieee80211_is_robust_mgmt_frame`) once the PTK is installed, as
  `ieee80211_tx_h_select_key` does. `packet_tx::management` then sets
  `MT_TXD3_PROTECT_FRAME` (mt76_connac_mac.c:571) and refuses protected
  multicast or data. This covers ADDBA/DELBA, SA Query responses and the
  closing deauthentication, which `ieee80211_set_disassoc` sends before the
  key flush.
- RX: `StationSecurity::admit_management` is `ieee80211_drop_unencrypted_mgmt`.
  Under PMF after the PTK, unicast robust frames need hardware CCMP
  metadata on key 0 with a strictly increasing management PN (security_idx
  `IEEE80211_NUM_TIDS`). Group robust frames need a valid BIP-CMAC-128 MMIE
  under the installed IGTK, checked in software as
  `ieee80211_crypto_aes_cmac_decrypt`, with the IPN seeded from the KDE.
  Everything else is dropped before the BA, deauthentication and MLME
  consumers, so an unprotected deauthentication no longer ends a PMF link.
- SA Query: `sa_query_response` is `ieee80211_process_sa_query_req`. An
  admitted Request (category 8, action 0, at least 28 octets) from the
  BSSID to this station queues a Response with the same transaction ID on
  the control queue. That Response is protected under PMF.
- Tests (`drivers/wireless/mt7921/pmf`, against `FakeAp::wpa3_sae`/`with_pmf`/
  `with_igtk`):
  - SAE H2E and hunting-and-pecking: exact IGTK record bytes, unprotected,
    forged and plain broadcast deauths dropped, and the BIP deauth ending the
    link, then teardown.
  - Failures: wrong password, PMF-required against a non-MFPC AP, SAE
    against a WPA2-only AP, and malformed passwords or records.
  - WPA2-PMF: SA Query Request dropped unprotected and answered protected
    (exact frame and `PROTECT_FRAME`), management PN replay dropped,
    protected deauth accepted.
  - Teardown: a protected deauth precedes key retirement.

### SAE offload to nl80211 (wpa_supplicant 2.12 / NetworkManager)

The native `Wpa3Sae` owner is offered to userspace as a full-offload SAE
station. `Mt76Iface::supports_sae_offload()` is true, so the wiphy advertises
`NL80211_EXT_FEATURE_SAE_OFFLOAD` (38) next to `4WAY_HANDSHAKE_STA_PSK` (15).
wpa_supplicant then keeps SAE in its AKM selection, sends the password in
`NL80211_ATTR_SAE_PASSWORD` and waits for `PORT_AUTHORIZED`.

- `validate_join` admits the supplicant's SAE association elements through
  `validate_sme_ies_for(.., SmeRsna::Wpa3Sae)`. The RSNE must have one SAE
  AKM (8 or 24), CCMP-128, exactly MFPC|MFPR after the replay-counter bits
  are masked, no PMKID, and BIP-CMAC-128 or the default. The RSNXE may carry
  only the H2E bit. The owner still sends its own RSNE and RSNXE in their
  place (`JoinPlan::append_sme_ies` drops both).
- A WPA2-PSK join keeps refusing these elements, and an SAE join refuses
  the PSK ones.
- Tests: `drivers/wireless/mt7921/networkmanager` checks the advertised ext
  features and admission at 5200 MHz. `drivers/wireless/mt7921/pmf` checks
  that the owner, given these elements, joins `FakeAp` and reaches
  Authorized with PMF and the BIP IGTK. It does this for WPA3-only (H2E and
  hunting-and-pecking) and for a transition-mode AP (`with_sae_transition`:
  PSK+SAE, MFPC), with one RSNE and at most one RSNXE on the air.

### Advertised cipher suites

`Mt76Iface::cipher_suites()` lists what the owner implements: CCMP-128 and
AES-CMAC (BIP-CMAC-128, the `MCU_CIPHER_BIP_CMAC_128` IGTK). AES-CMAC is what
gives wpa_supplicant `WPA_DRIVER_CAPA_ENC_BIP`. Without it, a profile with
the default `pmf` never asks for PMF. AES-CMAC is only safe to advertise
together with the optional-PMF CONNECT path above. Linux mt7921 lists
mac80211's whole set (CCMP-256, GCMP-128/256, BIP-CMAC-256,
BIP-GMAC-128/256). This owner does not implement those, so it does not
offer them. The NetworkManager discovery test requires both CCMP and
AES-CMAC.

### Station statistics (GET_STATION, `iw link`, wpa_supplicant signal_poll)

`Mt76Iface::station_info()` answers for the associated AP, as mac80211's
`sta_set_sinfo` does:

- SIGNAL is the strongest chain of the AP's last frame. CHAIN_SIGNAL holds
  both chains, and SIGNAL_AVG is mac80211's `DECLARE_EWMA(signal, 10, 8)`.
  RX_BITRATE is the last data frame's rate.
- The receive path takes them from RXD group 3 (`NativeRx::rcpi`: the P-RXV
  RCPI word, or group 5's) and from P-RXV DW0. It counts only frames whose
  transmitter is the BSSID, on the operating channel.
  `link_stats::rate` decodes the CONNAC2 rate word
  (`mt76_connac2_mac_fill_rx_rate`). The bitrates are cfg80211's
  (`narf_wireless::rate`).
- The packets come from the netdev counters.
- The statistics reset with each association. Each station `PacketStep`
  carries a snapshot, and the iface keeps it until the link clears.
- TX_BITRATE, TX_RETRIES and TX_FAILED come from TXS (Linux
  `mt76_connac2_mac_fill_txs` with periodic TXS requests) and are a
  separate step.
- Tests (`drivers/wireless/mt7921/station`): rate words and reserved
  encodings, RCPI and the EWMA, and a live `FakeAp` association whose Beacon
  signal is recorded. Another transmitter's frame is not counted, and the
  statistics reset with a new association.

### Regulatory changes while associated (`reg_notifier`)

The station records the policy snapshot its grant and firmware limits came
from (`StationLink::applied_policy`). A domain with different rules, from
`iw reg set` or the AP's Country element (see the wireless spec §3.5), is
control work. `service_regulatory` re-admits the same BSS under the new
policy (`TxPermission::from_ap_heard`, keeping a heard-AP grant's
relaxation). If the operating channel, width and band are unchanged, it
installs the new grant and sends the channel domain (CE 0x0f) and power
limits (CE 0x5d), as `mt7921_regd_notifier` does through
`mt76_connac_mcu_set_channel_domain` and `mt76_connac_mcu_set_rate_txpower`.
Otherwise it ends the link (`reg_leave_invalid_chans`). Reinstalling
identical rules is no change. Test: `drivers/wireless/mt7921/regulatory`.

### Connection-quality monitor (`SET_CQM`, wpa_supplicant bgscan)

`supports_cqm_rssi` and `supports_cqm_rssi_list` are true.
`set_cqm_rssi` stores the configuration. The receive path counts the AP's
Beacons and their signal (`LinkStats::beacons`, `beacon_signal_dbm`). After
each station packet step, the iface feeds the newly counted Beacons (at most
eight per step) to `narf_wireless::cqm::SoftwareCqm`. That is mac80211's
software monitor for a vif without `IEEE80211_VIF_SUPPORTS_CQM_RSSI`
(`ieee80211_rx_bss_info`): `DECLARE_EWMA(beacon_signal, 4, 4)`, nothing
before four Beacons, the single-threshold hysteresis rule or the
`cfg80211_cqm_rssi_update` range for a threshold list. Each crossing is sent
as `notify_cqm_rssi`. The monitor restarts with each association. Linux
mt7921 programs the firmware RSSI monitor instead (`MCU_CE_CMD_RSSI_MONITOR`
+ the unsolicited event). The host monitor gives the same events from the
same Beacons. Tests: `wireless/cqm` and `drivers/wireless/mt7921/networkmanager`.

### Station power save (`SET_POWER_SAVE`, NetworkManager `wifi.powersave`)

`power_save_default()` is `Some(true)`. This matches mac80211 with
`SUPPORTS_PS | SUPPORTS_DYNAMIC_PS` (mt792x_init_wiphy) and
`CONFIG_CFG80211_DEFAULT_PS`.

- `set_power_save` stores the setting (`BOOT_POWER_SAVE`).
- The boot owner samples it into `StationLink::ps_wanted` before each
  packet step. While associated, a difference from `ps_applied` is
  control work (`keys_pending`).
- `service_power_save` sends `mt7921_mcu_uni_bss_ps`: UNI_CMD
  BSS_INFO_UPDATE, `{ bss_idx, pad[3] }`, then the `UNI_BSS_INFO_PS` (21)
  TLV with `ps_state` 2 (dynamic power save, firmware-timed) or 0 (awake).
- Each association starts awake (`ps_applied = false`), so the setting is
  applied again.
- Linux also enables the firmware beacon filter (`UNI_BSS_INFO_BCNFT`, drop
  other BSS beacons) with runtime PM. This owner still reads the AP's
  Beacons on the host (WMM/PHY changes, CSA), so the filter is not enabled.
- Test: `drivers/wireless/mt7921/power`.

### Radar and NO_IR channels

cfg80211/mac80211 let a station join an AP that already operates on a radar
(DFS) or NO_IR channel. Only `IEEE80211_CHAN_DISABLED` refuses a client
chandef, and the client never probes there. This owner does the same, on
evidence:

- `ScanReport::beaconed` lists the `(bssid, channel)` of every 2.4/5 GHz
  result whose own Beacon (subtype 8, not just a Probe Response) this scan
  received, for both passive and associated scans. The iface replaces it
  with the scan cache (`scan_beaconed`, `clear_scan_cache`).
- `resolve_join(.., follow_heard_ap = true)` (infrastructure station only)
  uses `TxPermission::from_heard_ap` for a beaconed BSS. The native join uses
  `TxPermission::from_ap_heard(.., heard)`. These evaluate the policy with
  DFS and NO_IR removed (`follows_heard_ap`). INDOOR_ONLY, power, bandwidth,
  unknown flags and every 6 GHz rule still apply, and the grant is marked
  `heard_ap`. `current()` re-evaluates under the same relaxation, so a rule
  that is removed, narrowed or loses power still revokes the grant.
- Active scans keep the strict grant, so these channels stay passive. The
  channel domain sent to firmware clears NO_IR only on the occupied channel,
  as for any grant. P2P clients never take the relaxation.
- The station leaves the channel when the associated AP announces a channel
  switch. This is a Beacon or Probe Response from the BSSID carrying CSA
  (37, length 3) or Extended CSA (60, length 4). On a radar channel, that
  is the AP vacating after detecting radar. The receive path sets
  `peer_lost`, fences RX/TX BA and returns `DeviceGone`, and userspace sees
  the link loss and reconnects. Following the switch in place, as mac80211
  does with a channel-context reservation, is not implemented.
- Tests (`drivers/wireless/mt7921/dfs`):
  - The grant rules on the US and world-NO_IR domains: INDOOR_ONLY and a
    removed rule still refuse, and `from_ap_heard` needs the Beacon evidence.
  - A Beacon is recorded and a Probe Response is not.
  - CSA and Extended CSA end a live `FakeAp` association, and the
    unchanged Beacon does not.

### Country-specific WMM constraints

Implemented as in Linux v7.2 net/mac80211/util.c
`ieee80211_regulatory_limit_wmm_params`, which mlme.c
`_ieee80211_sta_wmm_params` calls for each AC before `drv_conf_tx`
(mt7921_conf_tx → `mt7921_mcu_set_tx`):

- `TxPermission` keeps the primary channel's `RegulatoryDomain::wmm_rule_for`
  (cfg80211 `freq_reg_info` at `chandef.chan->center_freq`, `has_wmm`). The
  occupied-channel admission now accepts `WMM_ETSI` alongside `NO_P2P`,
  because a WMM rule constrains EDCA rather than forbidding TX. Other flags
  are still refused. Narrowed grants keep the rule.
- `wmm::Parameters::edca_limited` raises each AC's `cw_min`, `cw_max` and
  `aifs` to the rule's client values, and caps `txop` at `cot / 32`. The rule
  is indexed by the mac80211 AC (VO 0, VI 1, BE 2, BK 3) from the native
  BE/BK/VI/VO rows. With no rule the AP's values pass through unchanged.
- The association EDCA and every dynamic WMM update (`service_wmm_update`)
  program the limited rows. `Parameters` keeps the AP's values, so
  change-count comparison is unaffected. The teardown legacy EDCA (CW
  31/1023, AIFS 3, TXOP 0) already satisfies every ETSI client AC.
- Tests (`drivers/wireless/mt7921/wmm`):
  - Exact limit arithmetic against `WmmRule::ETSI`.
  - Permission selection: WMM_ETSI admitted, NO_IR still refused.
  - The limited association EDCA command.
  - A limited dynamic update (VO CWmin raised to 3).
  - The teardown legacy EDCA.

### TX fragmentation

Implemented as Linux v7.2 does it for mt7921. mt7921 sets no
`set_frag_threshold` op and no `SUPPORTS_TX_FRAG`, so
`ieee80211_set_wiphy_params` → `drv_set_frag_threshold` succeeds, and
iface.c `ieee80211_set_sdata_offload_flags` turns 802.3 encapsulation
offload off whenever `wiphy->frag_threshold != -1`. mac80211 then fragments
in software (tx.c `ieee80211_tx_h_fragment` / `ieee80211_fragment`), and mt76
(`TX_FRAG_LIST`, mac80211.c:485) marks each fragment in TXD2.

- `Mt76Iface::set_fragmentation_threshold` stores the validated threshold
  (256..=2346 even, or `u32::MAX` = off; EINVAL otherwise) in
  `BOOT_FRAG_THRESHOLD`, which `fragmentation_threshold()` reports. The boot
  owner samples it before every packet step (`Transport::step_network`).
- `Session::fragments` splits a unicast MSDU when its 802.11 MPDU plus FCS
  exceeds the threshold. As in `ieee80211_tx_prepare`, an A-MPDU frame
  (a TID with an active TX BA agreement) gets `IEEE80211_TX_CTL_DONTFRAG`.
  Each fragment repeats the (QoS) DATA header with ToDS and the Protected
  bit under a PTK, carries the fragment number, and has MoreFrags on all but
  the last. Each fragment holds `threshold - header - FCS` octets of the
  RFC1042 LLC/SNAP MSDU.
- `packet_tx::fragment` is the `mt76_connac2_mac_write_txwi` +
  `_write_txwi_80211` descriptor:
  - `MT_HDR_FORMAT_802_11` with `HDR_INFO = header/2` and the TID.
  - `MT_TXD2_FRAG` FIRST/MID/LAST (mt76_connac_mac.c:464–468).
  - The TID's AC queue.
  - No `FIX_RATE`/`BA_DISABLE`, because this is data with a unicast receiver.
  - `MT_TXD3_PROTECT_FRAME` for protected fragments, so the hardware
    encrypts each fragment with its own PN.

  It refuses management frames, a multicast receiver, Order/FromDS, and
  fragment 0 without MoreFrags. Both backends submit it on the data ring
  (`Backend::submit_fragment`).
- Each fragment waits for its predecessor's terminal completion: only one
  token is in flight, and the rest queue in `tx_fragments`. Further MSDUs
  are refused (Busy) until the last fragment completes. A rejected
  fragment, any data failure and teardown drop the remaining fragments; a
  teardown drains only the fragment in flight.
- Tests (`drivers/wireless/mt7921/frag`):
  - Open, WPA2, QoS and QoS+WPA2: exact headers, fragment count and
    lengths, the reassembled MSDU, and the TXD FRAG/format/protect bits.
  - Unfragmented MSDUs at the threshold and with fragmentation off.
  - A rejected fragment, teardown with queued fragments, and encoder
    refusals.

### 6 GHz station operation

Implemented for the 6E parts (MT7922, MT7921/MT7961 6E SKUs) on top of the
shared 6 GHz `JoinPlan` (wireless spec §3, "6 GHz JoinPlan"). Linux v7.2
references are under `drivers/net/wireless/mediatek/mt76/`.

- **Capability gate.** `six_ghz::qualified` requires the NIC
  `MT_NIC_CAP_6G` TLV (`phy->cap.has_6ghz`, mt7921/mcu.c:595), the 5 GHz
  band (`mt7921_set_stream_he_caps` registers the 6 GHz sband only inside
  `has_5ghz`, mt7921/main.c:209–224) and the 5 GHz HE profile. Without it
  `associate_station` refuses a 6 GHz BSS (`InvalidIdentity`) and
  `Mt76Iface::bands` reports no 6 GHz band.
- **Band identity.** 6 GHz channel numbers collide with 2.4/5 GHz ones, so
  a 6 GHz BSS is always `ScanBss.band = Some(Band::Ghz6)`. The native
  `channel::Band::Ghz6` has scan/power-limit tag 3 (mt7921/mcu.c:1167,
  mt76_connac_mcu.c:2227), channel-switch `channel_band` 2
  (mt7921/mcu.c:892) and RLM band `NL80211_BAND_6GHZ` = 3
  (`mt76_connac_mcu_uni_set_chctx`). RX descriptors carry 6 GHz channel n
  as RXD3 `CH_FREQ` `181 + (n - 1) / 4` (`mt792x_get_status_freq_info`,
  mt792x.h:368–379); `channel::rx_channel`/`from_rx_channel` encode and
  decode it, and the associated station matches received MPDUs on that
  value.
- **Local profile.** `six_ghz::local` builds the `SixGhzLocal`:
  - The 5 GHz HE capability, which `mt7921_init_he_caps` reuses unchanged
    for 6 GHz (mt7921/main.c:14–150).
  - The HE 6 GHz Band Capabilities from the 6 GHz branch
    (mt7921/main.c:165–189): Minimum MPDU Start Spacing from the 5 GHz HT
    A-MPDU density; Maximum A-MPDU Length Exponent, Maximum MPDU Length and
    the antenna-pattern bits from the 5 GHz VHT capability.
  - The regulatory rule covering the BSS primary (`freq_reg_info`).
- **Grant and power type.** `TxPermission::from_ap` asks the shared
  `six_ghz::plan` for the channel, width and AP power type (LPI/SP/VLP,
  `cfg80211_6ghz_power_type`). It grants only when every overlapping rule
  admits the whole occupied span at that width, the rule allows a client
  of that power type (`allows_6ghz_client`, `cfg80211_6ghz_power_type_
  valid`), and no other flag restricts it. One native decision is added:
  an LPI AP's client operates indoors under that AP's control, so
  INDOOR_ONLY is tolerated for LPI only. 320 MHz (CONNAC3-only
  `CMD_CBW_320MHZ`) and 80+80 MHz are refused. `current()` re-evaluates the
  grant against every new policy, as for 2.4/5 GHz.
- **Join.** `JoinPlan::prepare_native` dispatches a 6 GHz BSS to the shared
  `prepare_6ghz`. Only `Security::Wpa3Sae` is accepted (H2E is required by
  the shared plan); Open and WPA2 are refused with `Bounds` before any MCU
  command. The plan's channel and power type must equal the grant's
  (`SixGrant::matches`). Then, in Linux order:
  1. `mt7921_mac_sta_add` → `mt7921_regd_set_6ghz_power_type`
     (mt7921/main.c:766–806): the package-selected CLC tables are re-posted
     with `env_6g` = `MT_AP_LPI`/`MT_AP_SP`/`MT_AP_VLP` (mt792x.h:83,
     `__mt7921_mcu_set_clc` mt7921/mcu.c:1331).
  2. The channel domain (bw_6g/n_6ch) and `SET_RATE_TX_POWER` rows with band
     3 for the occupied 6 GHz channels.
  3. `CHANNEL_SWITCH` with `channel_band` 2.
  4. BSS basic with `phymode` `A|AN|AC|AX_5G` (`mt76_connac_get_phy_mode`,
     mt76_connac_mcu.c:1381–1383) and `phymode_ext` `PHY_MODE_AX_6G`
     (mt76_connac_mcu.c:1603–1604).
- **After association.** The HE profile comes from the plan's
  `SixGhzPlan::he()` negotiation. The BSS records, HE_BASIC/BSS_COLOR and
  MU EDCA are sent as for 5 GHz HE, and UNI_BSS_INFO_RLM carries the 6 GHz
  channel with band 3.
- **Peer record** (`mt76_connac_mcu_sta_cmd` for a peer with no HT/VHT
  capability):
  - WTBL_HT with `af`/`mm` from the AP's `he_6ghz_capa`, then WTBL_VHT and
    WTBL_SMPS (`mt76_connac_mcu_wtbl_ht_tlv`, mt76_connac_mcu.c:977–1015).
    SMPS is off for a station's AP (`ieee80211_update_from_he_6ghz_capa`).
  - STA_REC_PHY `OFDM|HE`, with `ampdu` 0 because it is the absent HT
    capability's.
  - STA_REC_HW_AMSDU with the large-MPDU flag from the band capability's
    Maximum MPDU Length (mac80211 `agg.max_amsdu_len`).
  - STA_REC_HE and STA_REC_HE_V2.

### Colocated 6 GHz scan

Implemented as Linux v7.2 does it for mt7921, which sets
`WIPHY_FLAG_SPLIT_SCAN_6GHZ` (mt792x_core.c:711). cfg80211 therefore scans
2.4/5 GHz first, and `cfg80211_scan_6ghz` then builds the 6 GHz request
from the Reduced Neighbor Reports of those results.

- **Scan channel ids.** Native scan lists are `channel::rx_channel` ids:
  2.4/5 GHz channel numbers, or the 6 GHz RXD `CH_FREQ` value
  `181 + (n - 1) / 4`, which cannot collide. `passive_scan::scan_request`
  writes a 6 GHz id as band 3 plus the 6 GHz channel number
  (`mt76_connac_mcu_hw_scan`, mt76_connac_mcu.c:1820–1832). `beacon`
  decodes a 6 GHz `CH_FREQ` into `ScanBss { channel, band: Some(Ghz6) }`,
  and results are matched to the request and deduplicated by
  (BSSID, channel, band).
- **Request policy** (`iface.rs` `scan_channels`):
  - 6 GHz is selected only by frequency (a bare channel number never
    selects it), and only with `MT_NIC_CAP_6G`. Without it,
    `colocated_6ghz` and 6 GHz frequencies are `NotSupported`.
  - A default `colocated_6ghz` scan adds the whole 6 GHz sband, as cfg80211
    does. A default scan without the flag keeps its 2.4/5 GHz profile.
- **Split scan** (`Mt76Iface::scan`): the 2.4/5 GHz channels are scanned
  first. `six_ghz_scan_ids` then collects `scan::parse_colocated_aps` from
  every 2.4/5 GHz result and asks the shared `scan::plan_6ghz_scan`
  (`cfg80211_scan_6ghz`) for the 6 GHz channels: PSC channels blind unless a
  directed scan found its colocated ESS, plus every RNR-reported channel
  that matches the SSIDs. Without the flag every requested 6 GHz channel is
  scanned. A second firmware scan covers those channels, and both result
  sets fill the scan cache, from which a 6 GHz association (§3, "6 GHz
  station operation") is looked up by frequency.
- **Per-target fields: inapplicable to mt7921.** `mt76_connac_mcu_hw_scan`
  sends only the 6 GHz channel list. The RNR BSSID/short-SSID table built by
  `mt76_connac_mcu_build_rnr_scan_param` (mt76_connac_mcu.c:1713–1748) is
  consumed by mt7925 alone (mt7925/mcu.c:3110). `Scan6GhzPlan.targets` is
  therefore not programmed.
- **6 GHz is scanned passively.** The 6 GHz phase sends no SSIDs, and
  `ActiveScan` has no 6 GHz grant, so an active request naming a 6 GHz id
  is refused (`Authority`). Before the scan command, a scan that includes
  6 GHz publishes the channel domain with the 6 GHz sband appended, every
  channel NO_IR (`n_6ch`, `mt76_connac_mcu_set_channel_domain`). After the
  scan it restores the plain passive domain. Other scans keep their exact
  previous commands.
- **Tests:**
  - `drivers/wireless/mt7921/scan`: the scan-id and flag policy and the
    RNR/PSC selection.
  - `drivers/wireless/mt7921/six_ghz`: a Session 6 GHz scan with its band-3
    channel entry, the NO_IR 6 GHz domain around it, the 6 GHz result
    identity, refusal of active 6 GHz probing, and refusal without
    `MT_NIC_CAP_6G`.

### Passive monitor capture

`Mt76Iface` exposes STATION and MONITOR and implements the down-only
`set_iftype(2|6)` control. Existing nl80211 delegated interface administration
gates mode and `SET_WIPHY` frequency/width/center selection. Configuration is
retained while down; an admin-UP worker starts capture only after current
receive-policy and actual silicon validation. No default channel is assumed.
Twenty/forty/eighty MHz are supported on qualified bands and contiguous160
only on MT7922; six-GHz requires the real NIC six-GHz capability. Every
occupied twenty-MHz constituent and rule extent/bandwidth is validated.
NO_IR/DFS permit passive reception without granting transmission. Changing
channel requires DOWN, selecting the new definition, then UP. Explicit
MONITOR_FLAGS masks are unsupported and refused, including ACTIVE/injection,
error-frame and cooked/control flag requests; absent flags select this
passive raw OTHER_BSS/CONTROL default profile.

`Transport::{start_monitor,stop_monitor}` and the corresponding retained boot
controls own real UNI DEV/BSS records (monitor uses CONNECTION_INFRA_AP,
without AP peer/beacon state), a NO_IR-only domain, full-power policy,
OTHER_BSS/CONTROL receive filters and acknowledged UNI SNIFFER enable plus
channel TLVs. Native setup drains the completed pre-generation RX prefix
before publishing a new capture owner. That owner matches the netdev snapshot
captured before setup, including its packet generation, and rechecks the
registered ACTIVE identity; stale setup cannot capture or update carrier on
a removed/rebound same-name interface. `State::Monitor` exists only after
all receipts; cancelled setup/stop remains Running with its DMA owner until
verified recovery. No station port, key, BA, data TX or injection grant follows
from monitor state. Stop disables sniffer, restores filters, deactivates the
monitor BSS/device and disables the MAC before returning RadioReady.

All four CONNAC2 receive decoders extract RXD3 `CH_FREQ` from bits15:8,
matching `mt76_connac2_mac.h`:250–252. Bits17:16 are the independent native
`ADDR_TYPE`, with U2M value1; bit16 is not a ninth channel bit. Station/scan,
unkeyed AP raw RX and passive monitor capture preserve the original address
bits and frame bytes while decoding actual2.4/5/6-GHz channel tags. Directed
probe responses and normal unicast packets therefore use their actual channel.
The three new native descriptor regressions and updated channel/replay cases
remain pending executed validation. This correction neither relaxes cipher/
FCS/extent checks nor establishes current interface, decryption or RF authority.

The bounded sixteen-packet native receive step validates declared RXD extent,
normal/forwarded format, every optional group/pad, actual RXD frequency and
original 802.11 header. It preserves ciphertext and optional four-address,
QoS and HT-Control bytes. An undecryptable protected MPDU remains encrypted;
a descriptor already marked as decrypted/stripped, header-translated or
hardware-split A-MSDU is refused rather than reconstructed as an original
on-air frame. FCS/MIC-error descriptors are dropped (native drop_err policy);
no synthetic validity flags are emitted. Radiotap reports only actual
frequency and optional RCPI-derived dBm signal from group3/group5. Missing
PHY metadata stays absent. Raw control frames, including ten-byte ACK/CTS,
are bounded independently of the station parser.

The real registered radio delivers these captures through the shared net
monitor API to authorized AF_PACKET readers, with link type803,
ETH_P_802_2 and PACKET_OTHERHOST. It never enters station IPC rings,
Ethernet/IP/XDP ingress or the station RX epoch. Mode/DOWN/native stop/rebind/
namespace transitions retire the opaque net capture token and bound packet
hooks. An old socket must explicitly bind again for a new generation. DOWN
immediately fences publication before asynchronous native stop; removal and
suspend likewise close the token first. Policy or device failure closes
capture and retains native ownership until stop or verified reset.

Dated software validation (2026-10-29): native sniffer/descriptor/radiotap,
actual secured station→monitor→station retirement, net AF_PACKET generation/
namespace/mode rebinding and nl80211 authority/flag regressions passed x86_64
r10 and aarch64 r9/r10 selected runs. The aarch64 broad run excluded only
tx_ba, not monitor. Monitor software scope is closed; physical reception and
firmware/RF interoperability remain silicon acceptance work. Per-TID BA and
midstream TXS restart passed the full x86_64 r11 Wi-Fi run (2939 pass, zero
fail) and the corrected aarch64 r11 tx_ba subgroup (24 pass, zero fail).
Together with the aarch64 r10 broad run, all 323 registered MT76 software
tests pass on both architectures, with two expected hardware skips on each.
The per-TID and midstream restart software scopes are closed; real firmware
TXS/RF interoperability remains silicon acceptance work.

## 4. Invariants

- Register selector transactions preserve and restore unrelated latch bits.
- Descriptors, payloads and TX tokens retain ownership until validated terminal
  completion or verified device quiescence.
- Failed/cancelled operations cannot replay or release uncertain DMA. A new
  firmware generation requires verified reset/stop and ring retirement first.
  Behind a per-domain IOMMU, a completed blocking detach of the function is
  that verification for freeing; no ring is unmapped or freed before it.
  The domain is re-attached only after the device-side idle and
  bus-master-off proof.
- RX descriptor and native-frame rejection cannot fall back to treating device
  descriptors as Ethernet.
- Association/ring models do not establish firmware or RF operation on silicon.

## 5. Architecture notes

x86_64 and aarch64 compile the retained hardware backend and the same descriptor,
station and reset models. ARM device ownership transitions use outer-shareable
DMA barriers. `Transport::new` resolves the function's DMA configuration with
`narf_bus::dma::configure` (Linux `of_dma_configure`: the PCI host bridge
node's `dma-coherent`/`dma-noncoherent`, arm64 default non-coherent; x86_64
always coherent) and allocates every descriptor ring and per-slot frame buffer
with `narf_io::alloc_coherent_for` (`Ring::allocate_for`, Linux
`mt76_dma_alloc_queue` → `dma_alloc_coherent`). Coherent functions keep the
unchanged write-back buddy path. A non-coherent function gets its
`memory-region` `shared-dma-pool`, else the `linux,dma-default` pool, mapped
Normal-NC (Linux `memremap(MEMREMAP_WC)`), so device DONE write-back into the
16-byte descriptors never races a cached line; without a reserved pool the
transport refuses to start (`Error::Allocation`) instead of using write-back
RAM, because NARF never remaps System RAM non-cacheable (Linux
`DMA_DIRECT_REMAP` has no NARF equivalent). Software coverage:
`drivers/wireless/mt7921/ncdma`, `io/ncdma`, `bus/dma` and the
`firmware/fdt` DMA smokes, with synthetic non-coherent devices — no
non-coherent silicon has been tested.

Per-domain IOMMU: Linux mt76 has no IOMMU-specific code; it uses the DMA
API and iommu-dma supplies IOVAs. `Transport::new` no longer rejects
`narf_io::iommu::IommuMode::PerDomain`: there `narf_bus::dma::configure`
attaches the function to its default IOMMU domain
(`narf_io::iommu::default_domain`, Linux `iommu_setup_dma_ops`), every
`Ring::allocate_for` buffer is mapped through it (`alloc_coherent_for`,
Linux `iommu_dma_alloc`; 32-bit IOVAs tried first, so the 32-bit
descriptor-base check holds), and the driver programs the returned IOVAs
(`DmaBuffer::dma_addr`) exactly as before. Ring teardown unmaps each buffer
with PTE clear → IOTLB invalidation + wait → IOVA free → frame free.
Linux `mt7921_pci_probe` sets `dma_set_mask(&pdev->dev, DMA_BIT_MASK(32))`
(mt7921/pci.c:330), so behind the IOMMU every frame buffer is mapped with a
32-bit mask too; Identity keeps the 36-bit reach for non-data rings.

The hardware transport copies every frame into these ring slots, so the
domain-mapped rings are the whole device-visible surface: MCU WM/FWDL
command and firmware-download payloads, data TX (token-owned slots), and
the three RX rings. WFDMA prefetch (`0xd4600`/`0xd4680` EXT_CTRL) is
on-chip SRAM and takes no host address. The interface netdev frame
buffers (`iface*.rs` `alloc_coherent`) and the Stage-4 model `dma.rs` /
`txrx.rs` rings are never programmed into WFDMA.

DMA quiescence behind the IOMMU (`narf_io::iommu::block_device_dma` /
`restore_device_dma`, Linux `pci_dev_reset_iommu_prepare`/`_done` and
the blocked release domain before `iommu_dma_free`; brcmfmac is the
other user):
- **Stop.** `release` runs after the device-side proof (DMA_EN clear, idle,
  bus mastering parked, ring bases cleared). It then blocks the function
  (`Hardware::unpublish`) and only then marks the rings unpublished. The
  rings are freed later, when the owner drops, with strict per-buffer
  unmap: PTE clear → IOTLB invalidation + wait → IOVA free → frame free.
  A block that fails (`Timeout`) keeps them published.
- **Reset and recovery.** `park_bus_master` blocks right after the
  verified BME clear, so the WFSYS reset of `recover` and a recovery that
  dies both leave the function blocked. Retained rings are recycled in
  place. `initialize` re-attaches the retained domain (`restore_dma`) after
  its idle proof and before the first ring base write. `resume_dma`
  refuses a blocked function.
- **Dead firmware / unproven drop.** A `Hardware` dropped with rings still
  published blocks the function and, only if the block completed, frees
  them (`block_for_reclaim`). Otherwise `Retained` keeps them forever, as
  before.
- **Re-attach.** `Transport::new` restores a function that an earlier
  generation left blocked (`restore_function_dma`) after verifying bus
  mastering is off and before its first allocation.
- **Identity / disabled.** The block reports `Untranslated` and touches no
  IOMMU. Ordering, physical bus addresses and the retained-forever
  unproven owner are unchanged.

  - `mt7921_iommu_stop_blocks_then_frees`.
  - `mt7921_iommu_dead_owner_blocks_before_reclaim`.
  - `mt7921_iommu_recovery_restores_before_reallocation`.

All of these run against the recording `iommu_model::ModelIommu` backend

  `mt76_ptk0_replacement_overwrites_wtbl_key_in_place_after_m4_without_disable`

  `mt792x_init_wiphy` (:795–807) conditionally adds NAN/NAN_DATA when both

  MT7961_1a and MT7922_1 images all contain feature byte0xc0 (CNM set, NAN
  clear), so that condition is false for these exact receipts. Build dates,
  SHA256 hashes and native release offsets are recorded in
  [the firmware receipt audit](../research/summaries/mt7921-firmware-features.md).
  A future supported-family artifact advertising both bits requires a new
  conditional software inventory; generic newer-chip mode code alone neither
  proves that capability nor justifies a permanent family-wide exclusion.
- **Active scans while associated / off-channel active scans: implemented.**
  See §3 "Associated and off-channel scans" for the retained RX/key/control,
  occupied-power and cancellation contracts. Firmware owns dwell and return;
  the driver does not turn scan completion into an association grant.
