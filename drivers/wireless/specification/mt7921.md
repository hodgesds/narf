(`drivers/wireless,wireless,verification/wifi-fixtures`): x86_64 2317 pass,

## 1. Purpose & scope

The built-in `narf-drivers-wireless-mt76` crate owns CONNAC2 PCI discovery,
register access, firmware/MCU transport and the MT7921/MT7922 radio interface.
The loadable-module build currently registers PCI IDs only.

## 2. Assumptions

The live transport targets x86_64 and aarch64 with coherent identity DMA and exclusive
device/BAR/latch ownership. Per-domain IOMMU mappings require a separate DMA
mapping implementation. Firmware and published DMA remain retained until
verified shutdown.

## 3. Public interface

`association::JoinPlan` preserves the MT76 public preparation/transition API
while delegating common IEEE frame logic to `narf_wireless::association` and
owning the additional WMM negotiation described below. `ScanBss`
aliases the shared `Bss`. MT76 retains its hardware rate mapping, firmware
peer/key/BSS record builders and regulatory TX permission; the common plan
receives a security mode without a PMK and grants no firmware/port authority.
Associated STA_REC PHY/basic and rate-adaptation records read the common plan's
response-negotiated rate set, with no scan-time copy. Management TX selects
the lowest actual basic bit rate (CCK11Mbps is ordered before OFDM6Mbps in
the bitmap but is not slower), and refreshes its selection after association.

Native discovery parks inherited BME and memory decode with INTx disabled,
verifies parking before BAR sizing, and enables/readbacks memory decode only after
the owned full control mapping exists. `pci::bring_up(device, cap)` requires the
current exclusive PCI cap; invalid authority or command policy returns
`ProbeError::Authority`. Probe discovery, L1 selector/data transactions and native
constructor/configuration/doorbell operations run inside actual current
`Cap::invoke`, rather than a prior `check_live`. Revoked native authority reaches
neither ECAM/BAR sizing nor DMA allocation/publication. Existing live rings and
uncertain posted DMA retain their previous ownership/stop contract.

`Firmware::open` invokes the registry lookup and each bounded patch/RAM copy
through the corresponding current capability. Only owned immutable vectors reach
pure parsers; no view or pointer escapes an invocation. Executable signature policy
remains the firmware registry/build contract. Real signed-registry epoch tests and
native actual-DMA/doorbell fixtures also verify revoked source/PCI authority before
invalid configuration, register writes or queue construction.

`probe` discovers supported PCI IDs and defers firmware startup until firmware
discovery completes. `Firmware::prepare/open` validates and owns patch/RAM
images; `Transport::run`, `initialize_radio`, `scan_passive` and `scan_active`
drive bounded startup and 2.4/5 GHz scans on firmware-reported bands.
`boot_status` reports retained state.
`firmware_transport::provision_boot_radio().await` also continues the same parked
binding after firmware or registry authority is staged late. When initial preflight
finds missing firmware assets or network registration authority, `start_boot` spawns a background
task driving `retry_preflight_until` across 120 attempts with 500 ms intervals, falling back to
verified reset recovery if a subsequent hardware boot attempt fails. Preparation copies
and validates both images before claiming discovery or allocating DMA. Preparation
failure permits retry; once claimed, the owned startup future remains retained
across cancellation of the caller. Concurrent provisioning returns `Busy`. A
started failure requires verified reset recovery rather than repeating startup.
Repeated provisioning of an initialized radio reuses the registered interface,
preserves association and administrative state, and rejects changed identity.
Interface publication attempts the shared signed regulatory bootstrap;
missing deployment policy leaves the passive interface TX-closed. The
interface and native association entry retry `reg::db::ensure_domain()` before
constructing transmit permission, so standalone MT76 does not depend on Intel
or another driver loading the staged policy. Active scans may also bootstrap
once at explicit entry. Running station/scan permission checks use only the
current installed snapshot; clearing it closes admission without reloading a
still-staged policy.

### Retained active scan

`Transport::scan_active(channels, ssids)` and
`firmware_transport::scan_boot_active` use the same retained VIF/MCU/RX owner as
passive scans. The public facade advertises four scan SSIDs, matching Linux
`mt792x_init_wiphy`. A nonempty list of up to four 0–32-byte SSIDs selects active
scanning; empty entries request a wildcard probe. Nonempty entries are packed
with Linux's specified-only SSID semantics; two probes per SSID are requested.
The facade normalizes an explicit active request without SSID entries to one
wildcard entry. The complete 1186-byte v1 request, binary SSIDs, wildcard and 39-channel
extension layout are checked against fixed wire vectors in `scan_reference.bytes`.
Historical source/output hashes are retained as provenance. Native Rust tests
exercise the real MCU/transport owner; no source extraction or C/Python compiler
workflow is maintained. These fixtures are not firmware or physical RF evidence.

`scan_active_with_ies(channels, ssids, extra_ies)` and
`scan_boot_active_with_ies` extend the same retained path with complete optional
Probe Request elements. The public facade reports the native600-byte budget.
The packed request retains1186 bytes: length is LE16 at224 and copied IE
content occupies226..826, before the v1 extension. Malformed extents,
truncated vendor/extension elements, oversized content and firmware-owned
SSID/Supported Rates/Extended Rates elements fail before scan setup writes.
Passive probe IEs remain invalid. Opaque probe content grants no association,
PHY, key or controlled-port authority. Existing no-IE APIs retain identical
wire bytes. Native600-byte, preflight, all-publication cancellation and active
scan→VHT/RX2 DHCP/IP vectors pass in the coordinated software suites.

`ScanOptions` and `scan_with_options`/`scan_boot_with_options` additionally
carry a per-request randomized source-address/mask pair for active or passive
scans. The family source advertises SCAN_RANDOM_MAC_ADDR. Like Linux
`get_random_mask_addr`, the native owner obtains fallible secure host entropy,
then resolves each byte as `(random & !mask) | (addr & mask)`. Firmware receives
that resolved address at1116..1122 with SCAN_FUNC_RANDOM_MAC bit0 alongside
split-scan bit5; it receives no mask and supplies no invented entropy proof.
The mask must fix the unicast bit and the supplied address must be unicast.
Malformed options, absent active RF authority, incompatible state/band and
entropy failure precede any scan publication or sequence/state consumption.
Passive randomization preserves NO_IR and never enables probes. The radio's
station identity remains unchanged, and an ordinary subsequent request clears
the random flag/address. Cancellation retains the same uncertain native owner.
Literal mask/address, entropy/authority/cancellation and randomized active-scan
to actual original-MAC Open/WPA2 DHCP/IP vectors pass in those suites.

Active admission requires the current authenticated host policy. Every selected
20 MHz channel needs full rule coverage and representable signed half-dBm power;
any overlapping DFS, NO_IR or narrower-bandwidth restriction denies TX, and the
lowest overlapping ceiling wins. Explicit prohibited channels fail before any
hardware/recovery writes. An implicit channel list is filtered to eligible
channels on actual firmware-reported bands and fails if none remain. Passive
receive geometry remains available without active permission. Active scans while
associated remain Busy; dwell-time and colocated-6-GHz
options remain unsupported and fail before dispatch.

Requested scan dwell control has no established nonzero CONNAC2 timing contract
in the local reference. Linux `mt76_connac_mcu_hw_scan` explicitly leaves this
owner's dwell/minimum/timeout fields zero. Packed fields alone do not establish
their units or supported firmware behavior; applicability remains unknown until
that contract is proven.

Before `START_HW_SCAN`, the owner first retains/reserves its running state,
prepares the unassociated NO_IR VIF if needed, and programs each selected
channel's host rate-power ceiling. The 2.4-GHz then 5-GHz ordering is independent
of scan channel order; the final SKU
row alone carries the global terminal marker. That band ordering is checked
against the unchanged Linux `mt76_connac_mcu_set_rate_txpower` with both requested
channel orders in the native transport regression. Every SKU message is followed by Linux's
correlated `REG_READ(PSE_BASE=0x820c8000)` barrier; the event kind, exact extent
and register identity must match. Only then is a legacy20 domain permitting
the selected channels published. Host country/channel/power permission is
rechecked between stages, immediately before the probe-producing scan command
and on each bounded receive poll. Firmware EFUSE/CLC limits remain in effect;
no measured board data or country authority is synthesized.

Successful scan completion must match the nonzero seven-bit scan sequence.
The owner restores its NO_IR-only idle domain before returning ScanReady, so a
later passive scan does not inherit probe authority. Native probe responses
share the bounded checked beacon parser/cache. A policy denial, malformed PSE
reply, hardware revocation, timeout or other failure makes the attempt terminal;
scan cancellation and domain closure are attempted when authority/ownership
permit, but neither command DMA receipt proves firmware idle or releases DMA.
Dropping a waiter at power/PSE/domain/start/idle-domain publication or during
the scan leaves Running and rejects replay until verified reset/reload. The
existing retained recovery worker handles that generation boundary. Native
regressions cover those publication points, stale completion refusal, policy
change before probes and during receive, exact power/domain sequencing, and
passive continuation. Live regulatory-source revocation is still bounded by the
shared cached-domain contract; current PCI authority is invoked at native I/O.

MT7920 selects `MT7920_FIRMWARE_WM`
(`mediatek/WIFI_RAM_CODE_MT7961_1a.bin`) with
`mediatek/WIFI_MT7961_patch_mcu_1a_2_hdr.bin`. MT7921 uses the distinct
`MT7961_FIRMWARE_WM` (`WIFI_RAM_CODE_MT7961_1.bin`) and `1_2` patch;
MT7922 uses its MT7922 RAM/patch pair. These pairs follow Linux mt7921's
device selection; matching parser layouts alone do not make them interchangeable.

`Mt76Iface` implements `WirelessNetIface` for legacy 20 MHz 2.4/5 GHz channels and has live
Open/WPA2 station dispatch and retained packet service. It derives frame-registry
authority, registers a real kernel transmit callback, delivers RX to the kernel
and IPC rings, and drives bounded DMA progress from executor and synchronous
network waiters. The station contract includes peer-bound RSNA, UNI3 key updates,
BMC WTBL/GTK setup, hardware CCMP replay windows and acknowledged disconnect.
Both initial and replacement CCMP keys use native `STA_REC_KEY_V2` tag17
(`STA_REC_MURU` is18). The key TLV copies Linux `enum set_key_cmd` directly:
installation is0 with one cipher, removal is1 with no cipher; these values
are not an add/remove boolean. Native literal tests cover secured peer/PTK/GTK
installation and both WCID removals, including the complete key TLV extents.

### Negotiated WMM prerequisite

A scan BSS with one valid WMM v1 Parameter IE selects an automatic, restricted
WMM station profile. All four distinct ACIs, AIFSN/CW geometry, reserved bits
and complete IE extents are validated before any device writes. BE admission
control is rejected because there is no TSPEC owner. An Information IE alone
does not supply contention parameters and retains the normal legacy profile.
Caller-supplied WMM/HT IEs remain rejected by the common SME guard; the driver
appends its own WMM Information IE with U-APSD and service-period bits clear.

After the common association response binds the peer, status, AID and legacy
rates, the driver requires a valid WMM Parameter IE in that response. Missing,
duplicate or malformed parameters terminate the attempt before EDCA or a QoS
peer is published. A valid updated response parameter set replaces the scan
copy. A non-WMM scan profile retains non-QoS legacy behavior even if the AP
response contains unsolicited WMM parameters.

The retained owner emits Linux CONNAC2 CE `SET_EDCA_PARMS` (0x1d), with four
ten-byte rows in BE/BK/VI/VO ACI order and BSS/WMM set zero. CW values use
`(1 << ECW) - 1`; TXOP values retain their 32-us units. The host has no
country-specific WMM-rule API yet, so its sole selected BE queue uses
`AIFSN >= 3`, `CWmin >= 31`, `CWmax >= 1023` and TXOP zero, including more
restrictive AP values. The other ACs are programmed but never selected. A
matching, exact-size MCU PSE register read bounds command progress before
associated BSS_INFO_QBSS (tag 15), STA_REC_BASIC and WTBL_GENERIC QoS bits
are published. This is an
ordered native command path, not a fabricated EDCA acceptance event.

Only a fully associated Open or completed WPA2 controlled port enables QoS
Ethernet TX. Every frame uses BE LMAC queue 1, TID zero and native QoS DATA
subtype fields in TXD2/TXD7. The installed PTK remains the only encryption
authority. EAPOL retains its driver-owned non-QoS management-TX path. Native
QoS RX retains separate per-TID CCMP replay windows; descriptor, token and
payload retirement still require both DMA and firmware completion. No U-APSD,
TSPEC, priority selection or QoS Null is enabled. The separate negotiated HT20
profile below can additionally admit HT rates and bounded A-MSDU RX.

Station power setup now drains the host SKU command through the same correlated
PSE read used for active scans before any management TX. Association admission,
EDCA programming, terminal association and each management/Ethernet submission
recheck current PCI authority and signed host country/channel permission. A
country change, restrictive overlap or lower power ceiling cannot reuse the
earlier programmed grant. Each station BSS/peer/controlled-port/PTK/GTK command
checks permission before publication and after its matching receipt, and rekey
checks again before restoring Associated. Losing live permission clears the
host WMM/security/grant and makes the station terminal; explicit policy
reinstallation requires verified recovery and a fresh join. Receive-only policy
remains independent of TX.

A bound AP beacon/probe response with a valid changed four-bit WMM Parameter
Set Count now queues one owned contention update. Counter15→0 is a change,
exact repeats do not post commands, and successive received updates coalesce
to the latest complete set. Source MAC, BSSID, destination, native channel,
integrity and unfragmented management format must match the current station.
An unsolicited WMM IE cannot promote a non-WMM peer. Missing/malformed
parameters or changed contention rows with an unchanged counter still close
the connection until a fresh join.

Queuing an update blocks new DATA immediately while already-submitted native
tokens drain through both completion proofs. The retained control owner then
leaves Associated before its first wait, emits the same no-reply44-byte CE
`SET_EDCA_PARMS` body and checks the matching exact-size PSE read before
publishing the new set and restoring Associated. Current PCI and host
channel/power permission are checked before and after the native waits.
No peer/key reinstall, BA reset or PN/receive-epoch reset is performed for a
contention update. BE retains the conservative AIFS/CW/TXOP clamps above.
Pending key work runs first; an EDCA update cannot bypass a closed RSNA port.
Native Rust cases cover held DATA, literal native commands, counter wrap and
coalescing, Open/WPA2 per-TID replay, DMA/PSE cancellation, malformed progress,
policy loss, foreign/legacy beacons and actual replacement key receipts.
The existing WMM DHCP/IP compositions additionally perform a bound AP update
with their real negotiated PHY and BA owners before acquiring the lease.
These cases passed in the coordinated Wi-Fi suites: x86_64 2360 pass,0 fail,
9 skip; aarch64 1890 pass,0 fail,3 skip. Both production boots and btrfs
postflights were clean. These are scoped software totals, not physical RF proof.

Rekey retains negotiated WMM while its existing running state blocks ordinary
packets. Teardown retires host WMM/security/TX permission and pending EDCA
updates before its first wait; only a local one-shot permission can authorize the closing
deauth after a fresh policy/capability check. It removes keys/peers and restores BSS
QBSS/EDCA QoS zero before reusing the idle radio; verified reset clears all negotiation.
Cancellation or ambiguous EDCA/PSE completion retains the running/failed owner
and DMA until verified recovery, with no authorized station publication.

Native Rust smokes under `drivers/wireless/mt7921/wmm` exercise literal
EDCA/TXD wire fields, negotiation and response binding, malformed/downgraded AP
responses, current policy, per-TID replay, parameter changes, cancellation and
two-owner DMA retirement. An isolated real policy database additionally checks
clear/explicit-reinstall refusal, held QBSS receipts, all later Open/WPA2
port/key publication boundaries and rekey authorization restoration. Open and WPA2 composition runs the production
Session, reactive AP, netdev and DHCP client through a lease and exact
bidirectional Ethernet/IP data with negotiated QoS metadata. These tests do
not establish firmware/silicon interoperability; HT admission has its own
complete control/receive contract below.

### Negotiated HT20/HT40 station profiles

An actual HT-capable firmware radio and an AP with valid WMM parameters plus
singleton HT Capabilities/Operation elements can select native NSS1/2 HT20 or
policy-qualified HT40.
`HwCaps.ht_supported` follows that real radio capability, and
`WirelessNetIface::phy_capabilities(2400|5000)` returns the exact26-byte local
HT body: MCS0–7 or0–15 from actual NIC NSS, TX MCS defined/equal to RX,
SMPS disabled, SGI20, actual directional LDPC/RXSTBC1,3839-byte A-MSDU,
smallest A-MPDU factor and16-us density. The retained
family's Linux `mt76_init_sband` contract includes HT40/SGI40 when actual HT
capability is present. The raw NIC `max_bw` byte stays opaque: Linux declares
but does not interpret it, so it is not used as a command bandwidth enum.
Each Association Request offers only the
width permitted for that join. Unsupported bands, TX STBC and
NSS above the actual one/two-path NIC qualification remain absent.
The shared WMM parser owns wire validation; MT76 retains its native contention,
BE admission-control, power and current-authority policy.

The driver owns its HT Association Request element; arbitrary SME HT/VHT/HE
elements remain rejected. AP primary channel, HT element sizes/reserved SMPS,
nonempty first-stream RX MCS and mandatory basic MCS all require validation
before device writes. Required MCS outside the actual local receive set or
inconsistent with the peer's receive mask fails. The common supported/basic
legacy rate contract remains required for management/control rates; typed
HT membership-selector admission requires that real profile. A matching successful AP association response
must contain valid WMM and HT elements; a downgrade/missing response element
cannot silently turn an offered HT peer into a completed station. Its updated
HT capabilities replace the scan copy before any native HT peer publication.

After current host country/channel/power admission and native EDCA progress,
the owner programs BSS BASIC/QBSS HT mode and the source-defined20-byte unified
BSS RLM: actual primary/center channel, negotiated BW20/40, selected TX count
and actual RX chain mask. It then submits STA_REC_HT, PHY_TYPE_BIT_HT,
the peer's intersected full HT MCS mask in STA_REC_RA, nested WTBL_HT and WTBL_SMPS. Peer SMPS and A-MPDU
spacing/length constraints are retained. STA_REC_HT intersects SGI20 and, for
HT40 only, width/SGI40 with the bound AP response. SMPS masks its own bits
independently. CONNAC2 needs no invented CONNAC1-only WTBL_RAW GI write.
LDPC and higher MCS require the actual NIC and bound directional AP facts.
Existing BASIC/STATE/key fields and Open/WPA2 controlled-port receipts keep
their meaning. The native association receipts alone create no BA session.
The retained Transport then attempts the separate fresh-peer originator
transaction below before publishing carrier. TX A-MSDU remains disabled;
recipient RX BA has its own protocol owner below.
Every control/port/key command retains current pre/post-receipt policy checks.

The bounded receive owner is rebuilt from this exact response and remains
inactive until all native BSS/peer/security receipts and final current policy
checks succeed. Only then can native A-MSDU first/middle/last bursts deliver
atomic Ethernet payloads and commit one per-TID CCMP PN. Ethernet TX retains
native TXD3.BA_DISABLE until its separate originator transaction completes;
A-MPDU RX without a completed recipient agreement is
discarded before delivery or PN consumption. Unsupported peer-bound ADDBA
requests enter a four-response bounded decline queue. Supported requests use
the native recipient owner below. Cancellation, current-policy loss
or ambiguous native completion retains running/failed ownership and DMA; it
cannot restore an associated packet producer. Rekey/reset/teardown preserve
the earlier receive/permission retirement fences. Changed bound AP HT operation
or capability facts close the port pending a fresh join.

Nine native Rust smokes under `drivers/wireless/mt7921/ht20` cover literal
HT/PHY/RA/WTBL/SMPS/RLM bytes,2.4/5GHz Open/WPA2 negotiation, missing/malformed
response/preflight facts, native policy/cancellation boundaries, explicit ADDBA
refusal and non-BA replay ownership. Open and WPA2 production Session/netdev/
DHCP/IP compositions now exercise genuine negotiated HT20 and A-MSDU delivery,
without the old model-only receive activation. Firmware/RF interoperability
still requires acceptance on the actual device.

HT40 admission retains a driver-owned occupied-channel permission. Primary
and secondary must be valid retained channels20MHz apart in the same band;
5GHz pairs follow the canonical adjacent pairs in the native channel table.
AP HT40 support, allowed HT Operation width and SCA/SCB must agree; an
intolerant peer or unavailable40MHz rule leaves the20MHz path reachable.
One rule must cover the entire occupied40MHz span at40MHz or wider, and every
overlapping rule also constrains admission and the minimum power ceiling.
Only NO_P2P can be ignored for this station: DFS, NO_IR, INDOOR_ONLY and
unknown flags deny TX because this owner has no CAC/indoor qualification.
Current permission rechecks recompute the same full occupied span.

Before any authentication TX, native channel-domain BW20/40 enum0 admits
exactly both occupied channels, and a two-channel signed SKU command installs
their common minimum ceiling. Native CHANNEL_SWITCH uses width1 and the
actual center; unified RLM uses width1, HT-operation4 and SCO1/3. The driver
still transmits on one calibrated chain, while retained firmware CLC/EFUSE
limits remain authoritative. A bound association response that changes the
selected secondary/width fails terminally instead of retaining stale radio
state. Five `drivers/wireless/mt7921/ht40` smokes cover geometry, restrictive
secondary-only overlaps/current power, literal native domain/switch/RLM/peer
fields on both bands and sidebands, response downgrade, authority/cancellation
with retained DMA, and Open/WPA2 A-MSDU DHCP/exact IP. HT negotiation itself
cannot enable TX BA.

### Negotiated5-GHz VHT20/40/80 and actual-MT7922 contiguous160 station profile

The retained MT7921/MT7922 owner admits one transmit stream and one or two
receive streams, MCS0–8 at20MHz and MCS0–9 at40/80/160MHz, with the existing
Open/WPA2-CCMP, WMM and independent BA owners. The higher-rate/RX2/optional
coding continuation is implemented and covered by the coordinated software suites.
Actual GET_NIC_CAPAB must report HT, VHT, a5-GHz hardware path and supported
NSS. Native booleans and NSS are checked; the chip match table cannot create
these facts. Linux `mt7921_init_work` registers this family with VHT enabled;
`mt76_init_sband`/`mt76_init_stream_cap` provide the common≤80-MHz contract.
Only the separate actual-MT7922 branch adds160-MHz support in Linux. NARF
retains `Backend::chip_id()`/`RadioInfo.chip_id`, read from MT_HW_CHIPID under
current PCI authority by the hardware backend. Only actual0x7922 plus the
checked NIC qualification enables contiguous160 and SGI160. The default
model identity0, actual0x7961/0x7920 and PCI aliases cannot enable it.
Raw `max_bw` is retained as uninterpreted firmware data. EFUSE mode,
package/CLC world limits and current signed host power policy retain their
earlier meaning; no VHT board power or calibration values are invented.

`HwCaps.vht_supported` follows that actual NIC qualification.
`WirelessNetIface::phy_capabilities(5000)` supplies the exact12-byte implemented
VHT body: TX and RX maps0xfffe or0xfffa according to actual NIC NSS1/2,
SGI80, minimum A-MPDU exponent and3895-byte MPDU.
RXLDPC and RXSTBC1 are advertised only with their actual checked NIC facts;
TX STBC, beamforming, extended-NSS and80+80 remain absent. Actual MT7922 adds
contiguous160/SGI160 without deriving NSS from the chip ID. Its HT companion
advertises RX and TX MCS0–7 or0–15 with defined, equal TX/RX MCS parameters,
SMPS disabled, HT20/40, RX SGI20/40,
3839-byte A-MSDU and16-us density. The local receive facts are independent of
the AP receive mask or transmit-GI intersection. VHT remains absent on2.4/6GHz
and unqualified devices. Hardware capability reporting grants no channel,
association, key, BA or packet authority.

The driver opts into shared `association::phy::LocalPhy` and
`JoinPlan::prepare_with_phy` for this profile. The bounded parser retains the
original complete HT/VHT pairs; source-defined directional MCS/NSS intersections,
strict HT/VHT basic MCS, width/center and required membership selectors precede
native writes. HT selector0xff and VHT selector0xfe require their actual
selected profiles; HE/other mandatory selectors remain rejected. Caller PHY
capability/operation IEs cannot replace generated local facts. A matching
association response commits shared rates/PHY atomically, and native protection
or WMM rejection cancels the wrapper before it can remain associated. The
native first profile requires HT operation protection0; unsupported protection
cannot be silently copied into a radio that has not programmed it.

The advertised maps describe the radio's wider-band capability. The native
STA_REC_VHT maps separately cap a selected20MHz peer at0xfffd/0xfff5 for
TX1/2 and RX1/2 (MCS0–8).
Linux's `minstrel_get_valid_vht_rates` matrix excludes NSS1/2 MCS9 at20MHz;
LDPC does not override that rule. Both scan and response basic maps must remain
satisfied at the final width, including when an80MHz response narrows to20MHz.
An invalid initial requirement fails before device writes; a contradictory
response fails before native peer/key/port publication. Native directional
maps remain bounded by their respective scan and response facts. AP RX0–7
does not reduce the independently implemented local RX map or AP TX map.

The actual NIC PHY TLV's two-stream antenna/chain qualification now also
bounds TX2. The scan offer and matching response bound each directional
HT/VHT rate map; static SMPS clips TX to one stream, while dynamic SMPS
retains the native WTBL control. RA_INFO copies all ten MCS-mask bytes rather
than only MCS0–7. Native STATE RX-NSS follows the maximum usable HT/VHT
peer receive NSS, as in mac80211; a one-stream VHT map can coexist with
HT MCS0–15. HT20/40 on either band uses the same typed negotiation.

Initial management setup keeps one transmit path. Only the bound association
response can trigger a second native CHANNEL_SWITCH with TX count2 and
RX count2, before peer/key/port publication; RLM encodes TX count2 but RX
chain mask3. Width fallback reissues the same occupied-channel setup.
Every native wait and final commit retains current PCI and occupied-power
authority. Cancellation leaves the running owner closed and retains
uncertain DMA. Legacy or single-stream peers retain one native TX path.

Native host SKU rows reserve an additional conservative3-dB headroom when
the actual NIC has two possible RF paths, including active scans and
single-stream peers/rejoins. The signed half-dBm calculation is checked
before native setup; an unrepresentable ceiling fails without device writes.
The lowest occupied-channel EIRP applies to every native channel/rate row.
This is a host restriction, not a measured board gain or a replacement for
firmware EFUSE/CLC/SAR limits. The fixed single-path wire builder retains
its original bytes; production applies the checked path budget separately.
The same directional HT companion survives a policy-driven fallback on5GHz.

Eight new native Rust smokes cover genuine NIC1/2 capability replies,
HT20/40 and VHT20/40/80/160 RF/RLM/rate records, scan/response limits,
SMPS, signed power bounds, mandatory HT MCS8, cancellation and policy loss.
Typed HT retains source-defined CCK RX codes0–7 only on2.4GHz, with native
legacy width/GI/coding/stream bounds before PN admission;5GHz/VHT cannot
acquire CCK through fallback. Native rekey conversations still use valid
legacy basic rates. A bound response narrowing HT40 to20 triggers actual
RF/domain/SKU/RLM setup before the peer/port can open.
Existing Open/WPA2 DHCP/IP compositions now require actual TX2 RF/RLM/full
HT masks before acquiring their lease. These cases pass the native suites:
x86_64 2419/0 fail/9 skip; aarch64 1949/0 fail/3 skip. Physical acceptance remains.

Local RX LDPC is independent of local TX LDPC. Native TX LDPC requires the
checked NIC TX bit and AP RX LDPC in both scan and bound response, independently
for HT and VHT. The source WTBL_HT/WTBL_VHT `ldpc` bytes enable that TX use,
and sanitized STA_REC_HT/VHT capability bits follow the same intersection.
Local capability IEs preserve the actual RX promise even when AP RX LDPC is
absent. NIC LDPC and RX STBC bytes must be0/1 before they are used.

An80-MHz grant names the true primary, canonical center and all four20-MHz

### Native transmit queue and per-packet ownership

A genuine negotiated HT/WMM station can now keep up to eight independent
Ethernet MPDUs outstanding in the retained16-slot WFDMA data ring. This is a
native packet/ownership feature. Before an originator agreement, every packet
retains TXD3.BA_DISABLE; TX A-MSDU remains disabled for every profile.
Legacy/non-HT profiles retain their
one-frame path. An ordinary per-frame transmit future starts only on an empty
queue, so another producer's completion cannot satisfy that future.

Each submission retains its own native token, physical descriptor slot and
payload until both WFDMA DIDX/DDONE and that token's firmware TX-free status
are terminal. The producer advances on publication; an independent DMA cursor
checks only a submitted prefix, including wrap. Slot ownership and an eight
frame limit below the ring depth prevent full/empty aliasing or reuse of a
payload still held by firmware. A newer TX-free report cannot free an older
unconsumed descriptor. Firmware records may arrive out of order; software
retires the submitted FIFO only after both proofs for its head. The entire
native release event is checked for contradictory owned-token statuses before
any status is committed. Foreign tokens cannot complete an owned payload.

Every queued frame earns current device/channel/power admission separately.
Pending EAPOL/rekey or receive/transmit-BA control stops replenishment, drains all old
packet receipts and then runs the control owner. Keys/WCID cannot be removed
after only the first queued completion. A rejected packet or malformed/expired
native completion closes host security/grant/producer state while retaining
the uncertain tail. Oldest-packet deadlines cannot be refreshed by later
submissions. Cancelling teardown retains the running owner and every queued
packet; late terminal receipts do not restore association. Only verified
reset/quiescence/release/recycle clears an uncertain generation.

## 4. Invariants

- Register selector transactions preserve and restore unrelated latch bits.
- Descriptors, payloads and TX tokens retain ownership until validated terminal
  completion or verified device quiescence.
- Failed/cancelled operations cannot replay or release uncertain DMA. A new
  firmware generation requires verified reset/stop and ring retirement first.
- RX descriptor and native-frame rejection cannot fall back to treating device
  descriptors as Ethernet.
- Association/ring models do not establish firmware or RF operation on silicon.

## 5. Architecture notes

x86_64 and aarch64 compile the retained hardware backend and the same descriptor,
station and reset models. ARM device ownership transitions use outer-shareable
DMA barriers, in addition to the coherent-memory assumption. Non-coherent
platforms and per-domain IOMMU mappings remain unsupported. Waits use bounded scheduler-compatible futures
without holding IRQ-safe spinlocks across await points.

## 6. Dependencies

Bus/capability discovery, firmware registry, coherent DMA, scheduler/time,
wireless policy, cryptography and network/frame registries.

## 7. Stage assignment

Stage 5 bring-up. Production firmware/radio/scan and restricted station/data
paths have model coverage; physical acceptance is not established.
