# narf-drivers-cyw43439 — Specification

> Status: **v0.9** (signed exact host/card/board asset provisioning through
> discovered-core firmware boot and F2/station attachment; platform-specific wiring,
> broader profiles and target hardware acceptance remain open).
>
> Driver for the **Infineon (formerly Cypress) CYW43439
> Wi-Fi 4 + Bluetooth 5 combo SoC**, the WiFi chip on the Raspberry
> Pi Pico W and a number of low-power IoT modules. Transport and firmware
> implementation began from public/permissive references; the event codec
> now also uses Linux brcmfmac as a wire-layout reference under NARF's
> GPL-2.0-or-later license.

## 1. Why this part is the bright spot

The original public-document audit of the modern WiFi flagships
(iwlwifi, mt76, brcmfmac FullMAC, ath11k, mwifiex, rtw88) found
firmware-driven interfaces with limited register documentation. The
workspace now permits Linux GPL-2.0 driver references.

CYW43439 is the conspicuous exception. Infineon ships:

- A complete **88-page datasheet** (Rev. 03 / v05_00) covering
  pinout, the gSPI / SDIO host-interface electrical and protocol,
  the F0/F1/F2 SDIO function model, the backplane access primitives,
  and the chip-RAM upload procedure.
- **AN232689 Wi-Fi Software User Guide**, which documents the
  conventions a host driver uses across the gSPI link.

The IOCTL / IOVAR command numbering used inside the firmware itself
is *not* in the datasheet, but two permissively-licensed reference
drivers were written from public docs and explicitly avoid GPL Linux
derivation:

- **`soypat/cyw43439`** — MIT-licensed Go reference driver.
  <https://github.com/soypat/cyw43439>
- **Embassy `cyw43`** — Apache-2.0 / MIT-licensed Rust async driver
  used in production on the Pico W.

The original transport/firmware implementation uses the interface
conventions from those references. Linux reference use is identified
at the corresponding codec, so its provenance remains explicit.

## 3. Public interface and implementation stages

### Stage 1 (landed)
- Module + spec doc presence + reference list.
- Part-number / firmware-filename constants the loader will
  eventually need (`43439A0.bin`, `43439A0.txt`, `43439A0_clm.bin`).
- SDIO function model + backplane-core-id constants from the
  datasheet (no field-by-field bitmaps yet).

### Stage 2 — Transport (landed)
- **`gspi`** — 32-bit gSPI command-word codec (datasheet §6.4
  Figure 6-2 / Table 6-3): direction, auto-increment, function,
  17-bit address, 11-bit length. Round-trip + bounds-checked.
- **`sdio`** — CMD52 / CMD53 argument-word codec (SDIO Simplified
  Spec §5.1 / §5.3) plus the F0 CCCR addresses (`IO_ENABLE`,
  `IO_READY`, `BUS_IFACE_CTRL`, …) and the F1 backplane registers
  (`SBADDRLOW/MID/HIGH`, `CHIPCLK_CTRL`, `SLEEP_CSR`) from
  datasheet §6.5 Table 6-7.
- **`backplane`** — F1 32 KiB window paging codec: target-address
  → `(window_base, window_offset)` plus the three F1-register
  writes that program the window (datasheet §6.5).
- **`transport`** — `Transport` trait abstracting `(function,
  address) → bytes` over either gSPI or SDIO. Adapters live
  through `sdio_bridge`/`narf-drivers-sdio`, or platform SPI for gSPI.

`sdio_bridge::SdioTransport` adapts an owned `SdioFunction` host. F0/byte
controls use CMD52; F1 register words use CMD53 with the 0x8000 backplane
word-access flag; incrementing F1 RAM bursts split within the prepared
64-byte F1 limit. F2 commands stay within the prepared 512-byte limit.
F1 uses 64-byte blocks, F2 512-byte blocks. Preparation programs these FBR
sizes and enables F1 through the host lifecycle.

### Common FullMAC station seam

`fullmac::Fullmac` supplies command/event/data progress for both the SDIO BCDC
runtime and Broadcom PCIe msgbuf. `Station<R>` and `interface::Device<R>` now own
this runtime type. `interface::attach(name,packet_transport,clm)` preserves the
SDIO entry and wraps it in `Runtime`; `attach_runtime(name,runtime,clm)` initializes
and publishes a prebooted retained FullMAC owner. A separate active slot per bus
family permits SDIO and PCIe interfaces to coexist; shared synchronous drains
advance both owners without holding the active-slot lock across device work.

Each implementation declares its bus configuration and CLM requirements. CYW43439
continues requiring external CLM and disabling SDIO tx/rx glom. The exact BCM43602
PCIe profile embeds CLM and sends no SDIO glom commands. These are transport
policies; firmware/regulatory/MAC validation, station join/key events and controlled
port admission remain mandatory. Only the verified station lifecycle calls
`set_link`; transport completion alone never authorizes Ethernet. Disconnect and
link-down close the adapter before queued TX/RX can cross into another peer.

`Fullmac::BAND_5GHZ` defaults to false for the CYW43439 profile; its valid-channel
reply cannot promote a 5 GHz channel even when host policy covers it. The exact
BCM43602 implementation opts in and must confirm firmware 20 MHz bandwidth caps
before publication (brcmfmac §3). Common D11AC helpers validate band/frequency,
primary/center/sideband agreement and reject 6 GHz/4.9 GHz numeric aliases.
The common host-policy intersection preserves NO_IR/DFS channels for passive
reception, but requires every active-scan channel and association to pass all
overlapping transmit restrictions. The station retains its initialization
policy snapshot for fixed-domain initialization; native attachment observes live
shared DB replacement/clear as described below.

`Fullmac::VHT80` separately defaults to false. Only the exact retained BCM43602
PCIe adapter can probe native `vhtmode`/`txstreams` and qualify5GHz VHT80;
CYW43439 neither queries nor inherits that profile and exposes no VHT or5GHz
metadata. Sharing channel/association code does not promote this silicon.
The complete native BCM43602 VHT80 contract,80→40→20 fallback, four-quarter
power and original request/response proof are in [brcmfmac §3](brcmfmac.md).

### Stage 3 — Firmware load (landed)
- **`chipclk`** — F1 chip-clock-control register codec (datasheet
  §6.5 Table 6-7): force-ALP / force-HT request bits, ALP-avail /
  HT-avail status bits, plus the F1 sleep-CSR layout.
- **`core`** — AI identifiers distinguish CM3 (0x82a), SDIO (0x829)
  and D11 (0x812). Guessed fixed wrappers/write-only reset plans were
  removed. Live EROM discovery uses `brcmfmac::chip::Chip::discover_ai`;
  checked readbacks and deadline-bound AI reset helpers use Linux chip.c.
- **`firmware`** — one-shot ordered nine-step loader; wrong order/reuse
  fails. Firmware/NVRAM shape and token validate before bus I/O. It keeps
  the host one-bit width, requests ALP, requires chip 43439 with unique
  CM3/RAM/D11/SDIO cores, parks CM3, resets D11/RAM, clears bank-3 remap,
  derives RAM capacity from SOCRAM bank info (supported rev>=8 except12),
  checks firmware/NVRAM separation, streams RAM, releases discovered CM3,
  requests/forces HT, publishes protocol v4 and enables F2. No guessed RAM
  size or wrapper address reaches the live path. Status waits use common
  scheduler deadline primitives. `packet_core` appears only after success.
  `build_nvram_blob` appends the extra list NUL and word alignment; token
  length excludes its four-byte trailer, matching Linux firmware.c.
  `nvram_blob_address` returns `Option` on checked extent arithmetic;
  `into_transport` returns `Result` and rejects every unfinished/failed boot.

### Stage 4 — IOCTL / IOVAR codec (landed)
- **`sdpcm`** — SDPCM HW header (4-byte length + ~length checksum),
  SW header (8 bytes: seq, channel, doffset, fc-mask, max-seq),
  and BCDC IOCTL header (16 bytes: cmd, len, flags, status). All
  with bounded validation on decode.
- **`ioctl`** — `WLC_*` numeric command set (representative subset
  documented in AN232689) plus `build_request` / `parse_response`
  for full HW+SW+BCDC frame composition with 4-byte tail padding.
  `parse_response` surfaces non-zero BCDC status codes as
  `ParseError::ChipError(_)`.
- **`iovar`** — string-keyed variant (`WLC_GET_VAR` /
  `WLC_SET_VAR`) with payload encoded as
  `name + 0x00 + value`. Common IOVAR-name constants (`country`,
  `clmload`, `bsscfg:event_msgs`, `escan`, `pm`, `cur_etheraddr`,
  `bus:txglom`, …).
- **`events`** — async event codec on SDPCM channel 1: the
  Ethernet wrapper (`ether_type = 0x886C`), 10-byte `brcm_ethhdr`
  vendor envelope, 48-byte network-order `brcmf_event_msg_be`, and a
  representative `WLC_E_*` event-type set (`WLC_E_LINK`,
  `WLC_E_DEAUTH`, `WLC_E_ESCAN_RESULT`, …). `EventHeader::decode`
  reads the event message alone. `parse_event` receives the Ethernet
  frame after the transport/data headers are removed; it checks the
  vendor-long subtype, Broadcom OUI and event user subtype, returns
  `NotBrcmEventEnvelope` for a mismatch and `TruncatedPayload` if
  `datalen` exceeds the received data, and exposes exactly `datalen`
  bytes, ignoring padding. Event-specific payload byte order is
  retained. Regression coverage includes a literal Linux-format event,
  every truncated envelope length, truncated/oversized payload lengths,
  invalid envelope discriminators and zero/nonzero payload padding.

Transport/IOCTL constants cite their original public/permissive
references. Event-envelope and byte-order corrections cite Linux
`brcmfmac/fweh.h` and `fweh.c` explicitly.

### Explicit runtime and station interface

`transport::PacketTransport` returns one complete SDPCM packet (zero when
none), and TX copies finish before return. `SdioTransport` now implements
it: poll/ack discovered SDIO core mailbox and frame indications, validate
protocol v4/firmware-halt/global flow stop, read the first 64 FIFO bytes
then the checked remainder with fixed-address CMD53, consume four-byte
physical padding and bound each command to 512 bytes. TX follows Linux's
incrementing F2 writes. An empty readiness snapshot issues no FIFO command.
A drained zero header clears retained RX indication. `TransportError::Busy`
means no packet was submitted; runtime control/data retain sequence/credit
and continue bounded RX while waiting. Other FIFO failures poison reuse.

`bootstrap::register` installs standard SDHCI PCI class 0/1 registration and exact
F1 identity matches 02d0:a9af and 04b4:bd3d. The callback retains the whole initialized
card before scheduling provisioning via `drive_scheduled` across 120 attempts with 500 ms intervals.
`bootstrap::Provisioner::new(Card)` supplies
the same retained explicit-platform owner; `state()` and `provision().await` expose
Parked/Starting/Ready/Failed. `provision().await` verifies `trusted_net_authority` before
asset and regulatory validation. Native `bootstrap::provision_state/provision` accesses
the retained native instance. `boot(Card)` is a one-shot convenience; platforms
needing pre-boot retries retain a Provisioner instead.

The owning `Registers` must report immutable actual `pio::HostIdentity`; missing
identity fails before F1 preparation. A verified
`brcm/wifi-board-selection-v1.bin` NBSP record binds that exact PCI BDF/IDs/class
(or explicit platform MMIO identity), actual CIS F1 identity and discovered 43439
revision mask to a named board and exact executable/NVRAM/CLM keys, lengths and
SHA256 payload hashes. Format and offline builder are specified in
[brcmfmac §3](brcmfmac.md#3-public-interface). The manifest, NVRAM and CLM always
require verified signers even in an unsigned-executable developer build. Generic
`brcmfmac43439-sdio.txt` or 43439A0 filenames alone grant no board authority.

Registry/blob accesses use current capability invocation and retain original source
caps with copied bytes across the whole lifecycle. Actual source-cap revocation
fails the qualified SDIO adapter before F1/F2 command dispatch. Registry hot
replacement preserves pinned source bindings/bytes; a new selection rejects a
replacement with mismatched hash/length. Missing/invalid provisioning, unsigned
board assets or absent regulatory policy preserve the same Parked card and issue
no F1 setup commands. These conditions may be retried after staging valid inputs.
After the first F1 initialization attempt, cancellation/error is terminal; a second
provision call cannot reconstruct or reuse that owner.

A complete preflight validates signed selection, assets, single-board NVRAM with
boardrev and host regulatory policy, then performs F1 preparation, actual discovered
CM3 loader, F2/mailbox initialization and `interface::attach`. Actual chip/revision
must match the selected mask before any core reset or payload upload. The existing
nonempty/at-most-4-MiB executable rule is also checked from signed metadata and
actual copied bytes before Starting/F1 preparation; a knowably invalid staged
selection remains retryable. Actual RAM/image compatibility stays with the
checked discovered loader. Interface
names are reserved before awaited initialization. No synthetic MAC/calibration or
netdev appears before station setup succeeds. Platform clock/pin mux, regulator
and WL_REG_ON/reset authority remain with the actual platform owner; the manifest
never invents or configures them. The native profile is PCI SDHCI 3.3 V/one-bit legacy
PIO; Pico W gSPI/PIO wiring is a separate platform port.


`runtime::Runtime<T>` owns TX sequence/window credits, two reserved control
credits, priority flow stops and one correlated BCDC command at a time. The
command waiter drains RX itself under its caller's async mutex. A dropped
command poisons the session; late replies cannot complete another request.
The worker checks SDPCM lengths/checksums/offsets, bounds each call to 16
packets, and separates control replies, BDC Ethernet and Broadcom events.
Malformed or unsupported glom packets fail the session. Events have a
32-entry queue with explicit overflow failure; packet overload drops the
oldest packet. Unknown interfaces and stale IOCTL identities do not satisfy
a waiter. Transfer padding is excluded from the hardware header length.

`station::Station<T>` initializes the firmware IOCTL version, downloads CLM
in bounded chunks, applies the authenticated host country/power policy,
disables glom, starts continuously awake, reads the real MAC and valid channels and sets
the event mask. Its initial profile is 2.4 GHz D11AC-chanspec firmware API
v2, escan v1/BSS-info v109, Open or WPA2-PSK/CCMP with firmware supplicant
support checked at runtime. WPA2 authorization requires both successful
SET_SSID and FWSUP_COMPLETED, in either order. Firmware owns encryption,
replay and group rekeys; failed supplicant/link events close the port.

Ordinary station power save is exposed through `WirelessNetIface` with an awake
default. The retained receive worker applies the latest requested policy under
the station mutex: `WLC_SET_PM=86`, `PM_FAST=2` / `PM_OFF=0`, followed by
`pm2_sleep_ret=2000 ms` (Linux `brcmf_cfg80211_set_power_mgmt`). Applied state
commits after both correlated replies. Duplicate requests coalesce; a newer
request survives an older in-flight completion. Firmware rejection, partial
transition or cancelled command closes the port and prevents session reuse.
Native SDPCM tests cover wire values, queued TX cleanup, cancelled/late receipts
and request replacement; Open/WPA2 DHCP/IP models also enable and disable PS.
The host bus stays awake/polled; suspend, wake offload and bus PM still require
their own implementations and physical power/DTIM acceptance.
Query commands transmit the zero-filled query/output buffer prefix with the
original input copied into it. BCDC advertises the logical query length;
physical query input is capped to Linux's 1502-byte dcmd-body limit. SDPCM's
hardware length excludes alignment padding. Open clears `wpaie`; WPA2
programs its negotiated PSK/CCMP RSNE before join (ordinary no-PMF, or the
required-PMF profile below). Well-formed SME element
lists are accepted for offload after validating any requested RSNE against
that profile; firmware generates association capabilities and RSNXE.
Firmware roaming is disabled (`roam_off=1`) for the fixed-BSSID profile.
Failed joins poison the runtime: a disassociation IOCTL ACK cannot retire
old SET_SSID/PSK events, so reuse requires a fresh firmware lifecycle.
Terminal scan headers are correlated when present. Payloadless terminal
events follow Linux's contract, and failed/malformed/cancelled submitted
scans require reset before another operation can start.
Disconnect waits for the matching link-down event. Cancelled station work
fails the runtime before any late event can reopen the port. Reattach is
required after failure; automatic board reset/reload remains host work.

### Firmware-owned WPA2-PSK/CCMP PMF policies

The common station owner, also used by BCM43602, probes the actual firmware
`mfp` integer iovar as Linux `brcmfmac/feature.c` does. Firmware refusal leaves
ordinary Open/WPA2 reachable; malformed replies or transport failure cannot
manufacture support. AP/SME RSN negotiation admits required PMF only with actual
firmware MFP and supplicant support, MFPC accompanying MFPR, PSK/CCMP, and the
standard BIP-CMAC-128 management cipher (explicit or its standard default).
The published wiphy adds AES-CMAC/BIP to its CCMP cipher list only when both
actual firmware probes support this offload; unsupported firmware retains CCMP.
`supports_wpa2_mfp_offload()` also follows those actual probes. The shared
nl80211 PMK CONNECT path requires that separate capability, `USE_MFP=1` and
a strict PSK/CCMP MFPC|MFPR RSNE with explicit/default BIP-CMAC-128; a cipher
list alone cannot authorize it. The bounded optional profile below separately
advertises `supports_optional_mfp()`. Caller-requested
OCV or other additional RSN capability promises fail before native join writes
instead of disappearing from the canonical firmware RSNE.
Unsupported management ciphers, missing peer capability and contradictory/
duplicate/truncated RSN elements fail before the power/join writes. Existing
typed WPA2 requests can join an AP requiring PMF; a valid SME required-PMF RSNE
can request it on a capable AP. WPA3/SAE is not enabled by this change.

The driver emits a canonical MFPC|MFPR/BIP-CMAC RSNE and configures `mfp=2`
after WSEC, because cipher configuration can overwrite management-protection
state. An exact four-byte native readback must match. Open/ordinary WPA2
explicitly configure/read back NONE when MFP is supported. SET_SSID and the
same peer-bound FWSUP_COMPLETED key event remain mandatory for WPA2: neither
host RSN flags nor an IOCTL ACK opens the controlled port.

For required PMF, after those events the owner additionally queries current
firmware MFP mode, WLC_GET_BSSID and bounded eight-byte `assoc_info`, then reads
the actual `assoc_req_ies` and requires its canonical requested RSNE. All GETs
use the same source/power/country fence on every future poll and receipt as
active SET operations. Queries can consume fresh events/data, so another actual
FIFO/ring-idle event/data drain is required before port/carrier publication.
Wrong peer, malformed lengths, a downgraded actual RSNE, stale/absent policy,
missing key completion or cancelled native verification makes the submitted
join terminal. Late events or policy reinstall cannot revive it.

IGTK installation, BIP integrity/replay, SA Query and protected robust-management
acceptance belong to the firmware supplicant/MFP engine. The host never fabricates
an IGTK, key-installed event or protected-frame flag; this profile trusts the
configured native firmware's completed handshake and verified association facts.
Vendor deauth/link-loss events remain authoritative firmware decisions, including
when the firmware reports protected-peer loss. Raw management authentication is
not reimplemented over Ethernet. `Station::management_protection()` exposes only
completed metadata for the currently authorized peer; disconnect, peer loss and
failure close that metadata with the existing port/queued-TX lifecycle.

Five native SDPCM/BCDC smokes under `drivers/wireless/cyw43439/pmf` cover literal
mode/cipher ordering, actual association receipts, capability/readback/peer/RSNE/
length rejection, teardown, cancelled verification and production DHCP/exact IP.
They include raw nl80211 CONNECT parsing/execution through actual native PMF
receipts/port publication, missing-capability rejection without device writes,
and typed-SME OCV preflight rejection without join writes.

`supports_optional_mfp()` defaults off outside explicitly implemented owners.
The common FullMAC facade enables it only from its actual native MFP and
firmware-supplicant probes. Shared nl80211 advertises
`NL80211_EXT_FEATURE_MFP_OPTIONAL` only for that explicit contract. PSK/CCMP
`CONNECT` with `USE_MFP=2` requires both this capability and the required-MFP
offload capability, plus a canonical MFPC-only/MFPR-clear RSNE with zero PMKIDs
and default/explicit BIP-CMAC128. `USE_MFP=0` cannot silently acquire that
optional policy. Direct typed callers express the same policy through their
original MFPC-only RSNE; `AssociateRequest` gains no authorization boolean.

Native policy modes follow Linux `fwil_types.h` and
`cfg80211.c::brcmf_set_key_mgmt`: NONE0, CAPABLE1, REQUIRED2. Cipher programming
still precedes the mode set and exact four-byte readback. An explicit caller
MFPC-only request selects native1 even when the AP requires PMF; caller MFPR
selects2 and requires AP MFPC. The existing empty typed request still selects
required2 for an AP requiring PMF, and otherwise leaves ordinary no-MFP behavior.
An unsupported firmware, malformed MFPR-without-MFPC, contradictory caller
capabilities, OCV/extra promises or unsupported management cipher fails before
power/join writes. Open always uses NONE0 and never gains PMF from capability
advertisement.

Requested CAPABLE1 is distinct from negotiated protection. After exact peer
SET_SSID/FWSUP_COMPLETED, optional verification checks current source/occupied
policy, actual `mfp=1`, current native BSSID, bounded original request and
response IE snapshots, followed by another true native idle drain. The actual
request must retain canonical MFPC-only PSK/CCMP and BIP-CMAC128; the omitted
group-management suite is normalized only to its IEEE BIP-CMAC128 default.
The local security boundary checks exact RSN field consumption before that
normalization: no partial capabilities/count/PMKID/group-cipher field or trailing
byte is ignored. Valid legacy18-byte bodies and PMF default20/22 or explicit26
byte bodies retain their respective no-PMF/default-BIP/explicit-suite meaning.
If the bound scan AP advertises MFPC, an actual association-response RSNE must
retain that AP's MFPC/MFPR and PSK/CCMP/default-or-explicit BIP facts. Duplicate,
malformed, missing or downgraded response proof cannot report protection or
open the port. Against an AP without MFPC, absent/no-MFPC response evidence
permits an unprotected WPA2 association with `management_protection=false`;
configured native1 alone never changes that result. Unsolicited response
upgrade is refused. Required2 keeps its existing native obligation/handshake
contract, with consistency checks on any present response RSNE.

An MFPC AP that omits the response RSNE is admitted as a protected
association. IEEE 802.11-2020 9.3.3.6/9.3.3.7 include an RSNE in a
(Re)Association Response only for FT (and OCI/OWE cases outside this
profile), and 12.6.3 negotiates MFP when both the AP's advertised RSNE and
the STA's request RSNE set MFPC. The station verifies both (the selected
BSS's MFPC, the transmitted `assoc_req_ies` RSNE) plus the firmware `mfp`
readback; Linux v7.2 `cfg80211.c::brcmf_configure_wpaie` sets bsscfg `mfp`
from the connect RSNE and trusts firmware the same way, with no negotiated-
state readback. A present response RSNE must still agree. Firmware still
owns IGTK/BIP, SA Query, replay and robust-management validation. Native tests model its
source-correlated control/key events, not firmware-internal authentication.

Eight additional `drivers/wireless/cyw43439/optional_pmf` smokes pass on both architectures:
all NONE/CAPABLE/REQUIRED policies against no/optional/required-MFP APs,
native optional-capability gating, original request/response/default-BIP and
absence semantics, downgrade/duplicate/malformed proof, native mode/BSSID/extent
and exact partial/trailing RSN request/response/AP/typed-route faults,
caller OCV refusal, foreign versus genuine FWSUP, cancelled held mode/
request/response, policy clear during the actual response wait, raw Optional
CONNECT, and real Open/WPA2 protected/unprotected DHCP/IP including HT20.
Existing required-PMF smokes remain. These software vectors pass coordinated
gates; physical firmware PMF/optional interoperability remains unvalidated.
These tests model firmware offload decisions; they do not simulate firmware
EAPOL/IGTK/BIP cryptography or establish RF PMF interoperability.

### Firmware-qualified HT20/HT40 and short GI station PHY

The common Station probes actual `nmode` and `rxchain` using the native
brcmfmac `brcmf_setup_wiphybands` contract. Absent/off nmode remains legacy;
there is no guessed one-chain fallback. A positive nmode profile requires
native20MHz bandwidth constraints/readback before `WLC_UP` on each physical
band. Before narrowing, it queries each band's actual `bw_cap`; an optional
native `chanspecs` reply is a bounded `brcmf_chanspec_list` of count plus u32
entries (source1536-byte buffer, at most383 entries). HT40 requires both the
bandwidth bit and valid exact40MHz inventory entries. Missing inventory keeps
HT20; malformed count/extents fail closed. A missing RX-chain reply cannot
undo the20MHz limit. Zero/unknown chain masks or a mismatching configured
bandwidth readback fail closed. The source HT body offers SGI20 and, only on
independently qualified bands, HT40/SGI40. It retains
64K A-MPDU factor,16us density, actual one-to-three-chain RX MCS and defined
TX MCS. These are firmware offload capabilities, not fabricated host reorder
or calibration authority. The actual physical family/channel set still bounds
which bands `WirelessNetIface::phy_capabilities()` can expose; CYW VHT/6GHz is absent.

An HT AP additionally needs exact singleton HT Capabilities/Operation, the
current primary, a supported mandatory MCS subset and valid WMM parameters.
The selected AP's HT Operation chooses a20MHz profile or an exact supported
40MHz primary/secondary pair. Channel14, cross-band or invalid20MHz spacing
cannot form a40MHz profile. Both constituents must be firmware-reported valid
channels. A20-only firmware/band, absent exact chanspec, peer width/intolerance
restriction or insufficient current occupied-span policy selects20MHz before
device writes. HT40-intolerant peers cannot retain a40MHz admission.
`Station::ht_capabilities()` returns separate2GHz/5GHz optional capability
bodies; facade metadata never copies a band's40MHz bit into another band.
`Station::channel_width_mhz()` reports the connected native-verified20/40MHz CYW
occupied width, or absence after teardown/failure; it grants no TX authority.

Each40MHz grant covers the complete occupied span, all overlapping restrictive
rules, maximum bandwidth and minimum power. Only NO_P2P may be ignored for
station TX; indoor/DFS/NO_IR/unknown flags lack qualification. `qtxpower`
precedes widening. Before native40MHz `bw_cap=3` set/readback, both20MHz
constituents must return native `per_chan_info` VALID_HW/VALID_SW and the exact
band, without radar/passive/inactive/restricted or unknown flags. The join uses
the exact D11AC40MHz center/sideband encoding. A denied native constituent or
receipt cannot silently become a successful narrower association.

Before port publication the owner queries current BSSID, the exact selected chanspec,
bounded `assoc_info`, and the actual association request/response IE streams.
The request must carry the configured HT/SGI/MCS shape and WMM Information;
the response must preserve valid HT/WMM/current primary and the selected40MHz
secondary/width when requested. Post-submission width fallback/refusal is
terminal rather than an invented receipt. Every query and future resume uses
the current country/source/full occupied-power fence; queued data uses that
same retained grant. Clearing/restricting only the secondary therefore closes
the port and pending data; reinstalling policy cannot revive a failed lifetime.
Another actual FIFO/ring idle drain follows
verification. HT metadata requires the current peer/connection grant, and
disconnect/failure/cancellation cannot preserve or revive the port. Required
PMF verification composes with these PHY receipts. Firmware owns BA, reorder,
crypto and its Ethernet deaggregation; host tests do not simulate those engines.

Three `drivers/wireless/cyw43439/ht20` native smokes cover exact capabilities,
Open/WPA2/required-PMF DHCP and bidirectional IP, probe/peer/width/HT/MCS/WMM
denials, unsupported indoor/unknown TX policy and cancelled actual association
response verification. The common TX policy accepts no restrictive flag except
NO_P2P without an explicit qualification; passive receive remains available.
Five additional `drivers/wireless/cyw43439/ht40` native smokes exercise exact
40MHz/SGI40 replies in both orientations, Open/WPA2/required-PMF DHCP/IP,

request/response/width denials, live secondary-only revocation during queued

Their wider firmware replies test the common native owner; they do not assert
that deployed CYW43439 firmware or silicon supports40MHz. Actual20-only
capabilities remain HT20. Hardware/RF firmware interoperability is unvalidated.

The common interface now tags captured receive batches with a nonwrapping
association epoch. It validates current full occupied policy and native
source/bus/link/key progress after frame allocation, before one IPC publish
and before each unlocked stack callback. Host close retires old RX IPC and
queue admission immediately, even while native control or PS holds the async
mutex; a late receipt or same-peer rejoin cannot authorize an old batch.
State→publication→ring is the lock order. No state/publication/ring guard
crosses a stack callback; the publication guard never crosses an await.
Native descriptors/posted DMA still require their actual terminal owner proof.
Two new native CYW smokes prove no BCM VHT probes/capabilities, a native link
loss at both final receive boundaries, same-peer batch retirement and a fresh
positive receive control. These additions pass coordinated software gates;
they supply no physical PHY/firmware acceptance evidence.

`interface::attach(name, booted_adapter, clm)` is a real, explicit platform
entry point. It uses `reg::db::ensure_snapshot()` to preserve a caller-installed
policy or load staged signed `wireless-regulatory.bin` before live station setup.
Missing, unsigned or invalid bootstrap policy prevents attachment; no other
wireless driver must have populated the database. It completes firmware
setup before publishing wireless/frame/kernel netdev
registries. It requires live network registration authority and completes
capability-registry registration before publishing the active endpoint,
kernel netdev, wireless interface, or worker; registration failure leaves
those publication points untouched. A timer and synchronous kernel drains
call the same bounded progress method. State owns the TX consumer, one
pending frame and its deadline; each call services at most 16 F2 packets and
attempts at most one TX. A credit stop retains the frame for the next call
without holding the async mutex across a wait. Disconnect clears pending and
queued TX. Control operations use an async mutex; synchronous
network drains use `try_lock` and release it before network dispatch.
Traffic requires an authorized link and validates Ethernet source/destination;
firmware-owned EAPOL is excluded from the host data rings.

`Station::initialize_live(runtime, clm, Arc<dyn PolicySource>)` observes immutable
current policy snapshots from the shared DB (or an explicitly owned trusted
source); fixed-domain `initialize` remains available for platform/test callers.
Setup requires the original installation around WLC_UP and before publication.
Channel/power grants are rechecked on every native command-future resume
(including waits before credit-delayed publication), before/after control receipts,
during event/idle fences, before disconnect and station PS completion, and
immediately before host packet submission. Country changes, source absence,
removed/NO_IR/DFS channels or a power ceiling below the acknowledged grant close
host admission and poison the one-shot owner. Cached BSS, pending/queued TX and
late events cannot reauthorize it; same-country relaxation does not raise the
connection's acknowledged power. Reattach requires independently owned reset.
This observes DB replacement/clear, not automatic firmware-cap epoch revocation.
It makes no claim that already submitted or autonomous firmware RF has stopped;
uncertain transport/DMA ownership is retained until proven quiescent.

Physical carrier metadata is published only for the authorized link, alongside
the existing administrative up/down state. Disconnect, firmware failure and
terminal link loss clear carrier before queued data can pass; repeated drain
polls do not add carrier transitions.

Disconnect closes publication immediately and again after acquiring device
state, which serializes the final close with association/progress up publishers.
The composed firmware fixture deterministically publishes an old peer while
disconnect waits for state, then checks that completed teardown leaves carrier
and BSSID down and discards queued TX before any later worker poll.

The standard PCI SDHCI path registers and invokes the signed loader/FIFO
continuation above. Additional platform host discovery/power wiring is a separate
port and is not inferred from a chip MANFID or a generic firmware filename.

Registered runtime/station regressions drive actual worker/control methods
through credit wrap, flow stops, stale replies, event/data multiplexing,
CLM/identity/channel configuration, scan, Open/WPA2 association, disconnect
and cancellation. They establish software contracts, not radio/AP or host
controller interoperability. AP mode, suspend/resume and additional
virtual interfaces remain unsupported.

### Caller Probe Request IEs (implemented, common FullMAC)

`Station::scan` (shared by CYW43439 SDIO/BCDC and BCM43602 PCIe/msgbuf)
accepts `ScanRequest::extra_ies` through the firmware `vndr_ie` iovar, as
Linux `brcmf_cfg80211_scan` calls `brcmf_vif_set_mgmt_ie(...,
BRCMF_VNDR_IE_PRBREQ_FLAG, request->ie)` before escan. The body is a sequence
of `brcmf_vndr_ie` records, `cmd[4] count=1:u32 pktflag=0x10:u32 element`,
deleting the previously installed set before adding the new one; an unchanged
set is not reprogrammed, and an empty request removes the old set. Code:
`drivers/wireless/src/cyw43439/station_probe_ies.rs` (parser/encoder) and
`station.rs::scan_inner` (issued under the same receive/TX policy fence after
`qtxpower` and before `escan`).

Linux `brcmf_parse_vndr_ies` silently drops what firmware cannot carry. Here
a request fails before any device write instead, so a completed scan always
carried exactly the caller's bytes: non-Vendor-Specific IDs and WPA/WMM
(00:50:F2 type 1/2) vendor elements (firmware generates those) are
`NotSupported`; vendor bodies under five bytes or truncated TLVs are
`InvalidArgs`; more than `VNDR_IE_PARSE_LIMIT`=5 elements or more than the
512-byte `IE_MAX_LEN` saved buffer counting the 12-byte record header per
element is `NotSupported`. A firmware-refused or cancelled `vndr_ie` update
leaves the installed set unknown and poisons the one-shot runtime.
Smokes: `drivers/wireless/cyw43439/scan_ies` (two: literal add/del/no-op
lifecycle through the facade then Open association; refusal matrix with no
device writes, five-element boundary and terminal firmware refusal) and
`drivers/wireless/brcmfmac/scan_ies` (literal add/del ordering on the
native msgbuf ring for shared5/6). Firmware-internal Probe Request assembly
and RF transmission are not simulated.

### Negotiated WMM state and all-priority data (implemented, common FullMAC)

After the peer-bound SET_SSID/FWSUP receipts and any PHY/PMF verification,
the common `Station` queries the firmware `wme_ac_sta` iovar (four
`brcmf_cfg80211_edcf_acparam {ACI, ECW, TXOP}` rows) under the connection's
TX grant, as Linux `brcmf_get_assoc_ies` does, and ranks it with Linux
`brcmf_wifi_prioritize_acparams` (AIFSN+ECWmin+ECWmax; admission-controlled
VI/VO ranked as BE; all-equal ranks keep `brcmf_init_wmm_prio`). A firmware
refusal keeps the default map, as Linux's connect path does; a malformed
reply fails the submitted join. Another genuine FIFO/ring idle fence follows
the query before port publication. `Station::ac_priority()` reports the map
only for the authorized peer; disconnect or join failure resets it.
Code: `drivers/wireless/src/cyw43439/station_wmm.rs`, `station.rs`.

Data now uses all eight 802.1D priorities. The interface classifies each
frame with `cfg80211_classify8021d` semantics (RFC 8325 DSCP mapping; the
shared implementation in `ath11k::tx_hdr` is reused) as Linux
`brcmf_netdev_start_xmit` does. SDIO/BCDC carries the priority in the BDC
header; the SDPCM `fc_mask` stop is now checked at the
`brcmf_map_prio_to_prec` precedence derived from the negotiated map (802.1D
BE is precedence2), rather than at the raw priority. PCIe/msgbuf keeps one
station flow per `brcmf_flowring_prio2fifo` FIFO (created with the first
frame's priority as TID) and posts each frame with its own priority in the
TX descriptor flags. Smokes: `drivers/wireless/cyw43439/wmm` (ranking/
precedence/FIFO vectors; ACM-demoted negotiated map, classified BDC
priorities, disconnect reset and refused query), the extended
`drivers/wireless/cyw43439/runtime` flow-control smoke, and
`drivers/wireless/brcmfmac/wmm` (shared5/6 Open/WPA2 negotiated map, two
FIFO flows with TIDs0/6 and per-packet descriptor priorities0/3/6/7).
Firmware EDCA contention and over-the-air AC behaviour are not simulated.

### WPA3-Personal SAE firmware offload (implemented, common FullMAC)

Linux `feature.c` sets `BRCMF_FEAT_SAE` from the exact `cap` token `"sae "`
(never `sae_ext`). `Station::initialize` reads `cap` (512 bytes) and offers
offload (`supports_sae_offload`, nl80211 `SAE_OFFLOAD`) only with that token
plus `sup_wpa` (FWSUP) and `mfp`. `SecurityConfig::Wpa3 { password }`
(1..=128 bytes, `BRCMF_WSEC_MAX_SAE_PASSWORD_LEN`) toward an AP whose RSNE
offers CCMP and AKM 8 follows `brcmf_cfg80211_connect`: auth type 3,
`wpaie` (negotiated SAE RSNE), `wpa_auth = WPA3_AUTH_SAE_PSK` (0x40000),
wsec AES, `mfp`, `sup_wpa 1`, `wpaie` cleared, then the bus-match firmware
vendor's `set_sae_password` op: CYW (Cypress-ID 43439 SDIO) writes the
`sae_password` iovar `{le16 len; key[128]}`; WCC (Broadcom-ID 43439 SDIO,
BCM43602 PCIe; `bcmsdh.c`/`pcie.c` match tables) writes
`BRCMF_C_SET_WSEC_PMK` `{le16 len; le16 BRCMF_WSEC_PASSPHRASE; key[128]}`.
The vendor is fixed at attach (`Fullmac::firmware_vendor`, `FirmwareVendor::sdio`).
SAE always negotiates PMF (empty request RSNE: capable, or required for an
MFPR AP); `SET_SSID` plus `PSK_SUP`/`FWSUP_COMPLETED` authorize the port
and the firmware-built association RSNE is re-verified as for PMF-PSK.
A firmware `PSK_SUP` failure is terminal. Code: `station_sae.rs`,
`station.rs`, `station_mfp.rs`. Smokes `drivers/wireless/cyw43439/sae`
(ABI vectors; CYW/WCC exact order on SDIO and PCIe family seams incl. a
transition-mode MFPC AP; refusals without the token/FWSUP, bad passwords,
non-SAE/PMF-less APs with zero device writes; firmware SAE failure). They
use the scripted `fullmac_fixture` firmware over the shared `Fullmac` seam;
firmware-internal SAE commit/confirm and RF are not simulated.

### Firmware PMKSA cache (implemented, common FullMAC)

nl80211 `SET/DEL/FLUSH_PMKSA` now reach `WirelessNetIface::{set,del,flush}_pmksa`
(shared, additive; default -EOPNOTSUPP). The FullMAC `Device` keeps the
desired Linux `brcmf_pmk_list_le` (16 `{bssid, pmkid}` rows: replace same
BSSID, -EINVAL when full, compacting delete, -EINVAL for absent rows or a
missing BSSID). The worker and every association (before the join)
reconcile firmware: `pmkid_info` with the full v1 list, or for `wlc_ver`
major >= 13 (`BRCMF_FEAT_PMKID_V3`) a v3 flush (`count 0`) plus one
`brcmf_pmk_op_v3_le` per row with `time_left = NO_EXPIRY`; Linux leaves
PMKID v2 as a TODO and uses v1 there. A refused update leaves the firmware
list unknown and is rewritten next time. Code: `station_pmksa.rs`,
`interface.rs`. Smokes `drivers/wireless/cyw43439/pmksa` (list/v3 byte
vectors; v1/v3 reconciliation on both family seams with refusal and retry;
real CYW SDPCM device programming the list before `WLC_SET_SSID` and
flushing via the worker path).

### Firmware roaming and Fast BSS Transition (implemented, common FullMAC)

Firmware roaming stays off by default (`roam_off 1`, as before). The platform
enables it with `Device::set_firmware_roaming` (Linux `roamoff`), which
replays `brcmf_dongle_roam`: `bcn_timeout` 2 (4 when disabling), `roam_off`,
`BRCMF_C_SET_ROAM_TRIGGER {-75, BRCM_BAND_ALL}`, `BRCMF_C_SET_ROAM_DELTA
{20, BRCM_BAND_ALL}` and `event_msgs` with `BRCMF_E_ROAM`. A `ROAM`/success
event to a new BSSID while connected (`brcmf_notify_roaming_status`) closes
the host port immediately without a disconnect report. The worker confirms
it only after the firmware supplicant's `PSK_SUP`/`FWSUP_COMPLETED` from the
new peer: `WLC_GET_BSSID` must match, the firmware `chanspec` must be a
retained valid channel admitted by current policy under a fresh TX grant
(`qtxpower` re-applied), PMF is re-verified, `wme_ac_sta` re-ranked and
`assoc_info`/IEs re-read (`brcmf_bss_roaming_done`), then a genuine idle
fence precedes publication and nl80211 `NL80211_CMD_ROAM`
(`notify_roamed`, shared additive). Old-peer link loss after the roam is
ignored; new-peer deauth/link loss is a plain disconnect; key failure,
BSSID mismatch, an inadmissible channel or the 15 s budget are terminal.
The roamed link is reported at its firmware width but makes no HT/VHT
re-verification claim.

FT follows `brcmf_set_key_mgmt`: a request RSNE with AKM FT-PSK (4) or
FT-SAE (9) toward a BSS advertising a Mobility Domain element selects
`wpa_auth` `WPA2_AUTH_PSK|WPA2_AUTH_FT` (0x4080) or
`WPA3_AUTH_SAE_PSK|WPA2_AUTH_FT` (0x44000); firmware performs the initial
mobility-domain association and the over-the-air FT reassociation in its
roam, confirmed by the roam path above (PMKR1Name in the reassociation
RSNE is excluded from PMF profile comparison). Code: `station_roam.rs`,
`station_ft.rs`. Smokes `drivers/wireless/cyw43439/roam` and
`drivers/wireless/cyw43439/ft`; firmware roam decisions and FT key
hierarchy are not simulated.

### Per-AC queue/traffic telemetry (implemented, common FullMAC)

Linux brcmfmac exposes no per-AC/TID statistics through cfg80211
`get_station`; its per-FIFO counters are `fwsignal.c` debugfs only. The
common `Device` keeps the equivalent host accounting per IEEE 802.1D->AC
(`ieee802_1d_to_ac`) using the same `cfg80211_classify8021d` priority
the data path submits: frames/bytes handed to firmware, host queue drops
(credit timeout, disconnect/failure flush of the pending frame and TX
ring) and frames/bytes delivered to the stack. `Device::ac_statistics()`
returns VO/VI/BE/BK rows; `GET_STATION` reports their totals as
`tx_packets`/`rx_packets`/`tx_failed` while connected. Code:
`telemetry.rs`, `interface.rs`. Smoke `drivers/wireless/cyw43439/telemetry`
(actual SDPCM/BDC uplink EF/CS1 and downlink, station totals, VI drop on
disconnect flush). Firmware-internal per-AC airtime/retry counters are not
read: Linux has no per-AC counter iovar for this firmware ABI.

### Host-supplicant fallback (implemented, common FullMAC)

`SecurityConfig::External` follows Linux `brcmf_cfg80211_connect` with
`BRCMF_PROFILE_FWSUP_NONE`: the supplicant's exact RSNE (cached PMKIDs
included) goes to `wpaie`, its AKM to `wpa_auth` (`brcmf_set_key_mgmt`:
PSK 0x80, 802.1X 0x40, PSK-SHA256 0x8000, 802.1X-SHA256 0x1000), wsec AES,
`mfp` from its RSNE, `sup_wpa 0`, then the join; `SET_SSID` success alone
links up (`brcmf_is_linkup`). The port stays unauthorized: netdev data is
dropped both ways and EAPOL from the AP goes to nl80211
`CONTROL_PORT_FRAME` (`rx_control_port`, or the netdev without a
control-port owner). `tx_control_port` sends EAPOL/pre-auth to the AP as
802.1D 7. `add_key`/`del_key`/`set_port_authorized` are validated
synchronously (index < `BRCMF_MAX_DEFAULT_KEYS`, CCMP-128, pairwise peer
= AP: -EINVAL/-ENOENT) and applied in order by the worker:
`send_key_to_dongle` `wsec_key` (`brcmf_wsec_key_le`, pairwise with the
peer address, group `BRCMF_PRIMARY_KEY` with RX IV), `CRYPTO_ALGO_OFF`
deletion, then authorization. A refused key is terminal. Firmware roaming
is not combined with a host supplicant (a roam is reported as link loss).
Code: `station_external.rs`, `interface.rs`. Smokes
`drivers/wireless/cyw43439/external` (key/AKM vectors; PSK/802.1X/
PSK-SHA256 connect, keys and authorization on both family seams; SAE and
refused-key failures). Supplicant EAPOL content is not simulated.

### Random scan source address (not applicable to triggered scans)

`supports_scan_random_mac()` stays false. Linux brcmfmac exposes no random
source address for a triggered escan: `feature.c` sets
`BRCMF_FEAT_SCAN_RANDOM_MAC` only from the PNO `pfn_macaddr` iovar
(`feature.h`: "Random MAC during (net detect) scheduled scan"), and
`cfg80211.c` maps it to `NL80211_FEATURE_SCHED_SCAN_RANDOM_MAC_ADDR` /
`ND_RANDOM_MAC_ADDR` only; `pno.c::brcmf_pno_set_random` programs it for
scheduled scans. The escan parameters (`brcmf_escan_params_le`) carry no
source address. A random-MAC triggered scan is therefore refused rather
than sent from the permanent address. Scheduled/net-detect scan is not a
NARF FullMAC interface today; if added, its `pfn_macaddr` randomization
belongs with that PNO feature, not this triggered-scan capability.

An explicit disconnect error is terminal even when its IOCTL response was
correlated: firmware link-down remains unconfirmed. Software clears the peer,
poisons the runtime and blocks later join/TX until reset; late old LINK or
SET_SSID success events cannot reopen the port.

Physical carrier/peer publication does not change operator `IFF_UP` and never
invokes administrative open/stop hooks while retained driver state is locked.
Explicit registration, operator up/down and autoconnect remain administrative
events. Disconnect/failure clears carrier and peer identity while preserving an
operator-UP interface; a later physical carrier sample cannot undo operator DOWN.

## 4. Out of scope

- Bluetooth side — runs as standard HCI through the combo. The
  `narf-bluetooth` crate covers the HCI surface; the host driver
  here just routes the BT bytes to/from that crate.
- Higher-level 802.11 MLME — lives in `narf-wireless`.
- Firmware blob distribution — the loader path stages whatever the
  caller hands it; the blobs themselves are Infineon-distributed
  binaries the boot path supplies via the existing firmware-cap
  surface.


## 5. Architecture notes

The standard host uses exact-width MMIO and bounded synchronous PIO; PCI current
capability invocation checks decode/INTx/BME policy before every register access.
No host DMA lifetime is implied. Backplane/FIFO protocols and board selection are
architecture independent and use the same production paths on both kernel targets.

## 6. Dependencies

Implemented retained profile: standard PCI SDHCI 3.3 V, one-bit <=25 MHz PIO, actual
CIS function discovery, signed host/card/board asset selection, 43439 CM3/SOCRAM
loader, protocol-v4 FIFO/BCDC, 2.4 GHz scan/Open/firmware-supplicant WPA2-PSK/CCMP,
actual kernel DHCP/Ethernet/IP, explicit disconnect and terminal failure.
Deployment requires actual board identity, signed calibration/CLM/selection and
compatible executable assets, authenticated regulatory policy and physical host/AP
acceptance. A non-PCI platform additionally needs its real host/wiring owner;
standard PCI selection does not implement Pico W gSPI.

## 7. Stage assignment

Stage 5 software bring-up. Optional 4-bit/high-speed/IRQ/DMA, different host quirks,
WPA3/AP, suspend/recovery and additional interfaces remain outside this initial
polling profile. Failure requires a fresh proven board/firmware lifecycle; no
unconfirmed reset/retry is presented as recovery.

## 8. Verification and open questions

Existing reactive FIFO/FullMAC tests compose production Station/Device with actual
kernel DHCP and exact bidirectional IP on Open/WPA2. Independent NBSP literals now
run through real signed registry installation and current source-cap invocation.
A real initialized SDHCI/Card fixture proves repeated missing/revoked selection or
policy denial retains the exact card without F1 commands; first command-controller
failure makes provisioning terminal. Selected-revision loader tests reject a wrong
mask before any core-register mutation or payload and stream exact selected bytes
only for the admitted discovered revision. Revoked selected NVRAM blocks actual
SdioTransport command dispatch before F1/F2 I/O. These are software proofs using
synthetic nondeployment identities/assets; actual clock/power/reset sequencing,
RF calibration, SDIO electrical timing and radio/AP interoperability require target
qualification. Linux brcmfmac `firmware.c`, `pcie.c`, `of.c`, `bcmsdh.c` and `sdio.c`
are primary implementation references under `/usr/src/linux`.
